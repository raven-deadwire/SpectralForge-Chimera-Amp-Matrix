# Náströnd A2 v2 refinement, 2026-10-24

This run warm-starts from the first v2 training ([train-v2-20261024](train-v2-20261024.md)).
It uses 480 seconds of training capture; the validation, test and audition
inputs are hash-identical to the first run's. Quality profile
`nastrond-tone3000-fidelity-v2`. **Numerical accuracy: FAIL on all five.**
No release approval.

## Run

The run starts from the first run's selected models, with a fresh optimizer.
It trains 5,000 steps at LR 0.001 (2,000-step half-life) on 4,096-frame crops,
batch 2, with the legacy recipe, 10% terminal-decay crops and export-consistent
centering, on 4 CPU threads. It uses `train_a2.py` at `829cf61`. That commit
fixes warm-start model selection: the imported models are now scored with the
same five-excerpt metric that later steps are selected by. Before the fix, the
imported models were scored on the full signal and could never be replaced. An
earlier attempt without the fix kept step 0 for three channels; its results are
superseded by this run.

## Reading

- **Fenrir did not improve.** No checkpoint beat its starting excerpt ESR of
  0.220: the best was 0.256, at step 4,500. Its quiet failure, at −61.9 dBFS,
  falls on samples that have input history.
- **Ragnarok's peak error grew** from +1.14 to +2.48 dB while its ESR halved.
  Selection uses ESR only, so it can choose a state with a worse peak. A
  level-aware selection or peak constraint is needed before this channel can
  qualify.
- **Fimbulvetr is closest.** Its active median of 0.016 is about 3× its limit
  of 0.005, and its p95 is about 10× its limit.
- Training is still improving slowly at LR 0.0005. The gap is about 10×, not a
  marginal shortfall, so more steps alone are unlikely to close it. Data
  coverage, model capacity within A2-Full, or the loss would need to change.

## Reproduce

Capture with `capture_channels.py --train-seconds 480`. Then run `train_a2.py`
with the command in `refine-v2-20261024.json`, using the first v2 run as
`--warm-start`. Models, checkpoints and capture arrays are kept outside the
repository.
