# TONE3000 accepts only A2 NAM files, 2026-10-28

Question: could a wider WaveNet than A2 (for example 16 channels, which cut
Fenrir's full ESR by 34% in [capacity-diagnostic-20261026](capacity-diagnostic-20261026.md))
be shipped for TONE3000?

Answer, from the player source at the pinned commit `ef6f178`
(tone-3000/tone3000-plugin): **no.**

- `plugin/src/ProcessorModelLoader.cpp`, `namConfigIsA2`: every locally
  dropped `.nam` file must be a bare A2 WaveNet, or a `SlimmableContainer`
  whose every submodel is one. Anything else is refused with "Only A2 NAM
  files are supported". The comment gives the reason: the runtime is built
  around A2 (48 kHz, the slimmable tiers, the fast path).
- `NeuralAmpModelerCore/NAM/wavenet/a2_fast.cpp`, `is_a2_shape`: one layer
  array, no head, `channels == bottleneck` and equal to **3 or 8**, and
  kernel sizes and dilations exactly the fixed A2 tables.
- The tone browser likewise disables NAM tones that have no A2 model.

So width 8 is the ceiling for this player, and a `SlimmableContainer` adds only
smaller tiers, not a larger one. A wider model would play only in other NAM
players (for example the standard NeuralAmpModeler plugin), not in TONE3000.
