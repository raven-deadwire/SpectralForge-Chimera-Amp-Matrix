# Transpose 하이브리드 고정 지연 보고 설계 — 2026-10-23 KST

연구 단계 설계다. 대상은 `Tools/TransposeNext/HybridLowBandPitch.h`의 AL10RA-800(800 Hz LR4, 아래는 onset 재정렬 시간영역, 위는 10 ms STFT)이다. 제품 코드(`Source/`)는 바꾸지 않았다. 측정은 합성 소재뿐이며, 실제 DAW 왕복 지연·DI·청음은 하지 않았다. 배경 수치는 `docs/TRANSPOSE_SYNTHETIC_EVIDENCE_20261023.md`에 있다.

## 1. 문제

호스트 PDC는 플러그인이 보고한 고정 지연 L만큼 출력을 앞당긴다. STFT 모드(CLASSIC / LOW-LAT / TIGHT)는 모든 성분이 분석 창 길이만큼 늦어 L이 하나로 정해진다.

시간영역 읽기 헤드는 그렇지 않다. 다운시프트는 지연이 2 ms에서 40 ms 쪽으로 늘고, 업시프트는 줄어들다가 스플라이스로 되돌아간다. 이 지속 구간 지연은 원리상 고정할 수 없다. 앞 문서에서 지연 상한을 최저음 한 주기 아래로 줄이면 음정이 원래대로 돌아가는 것을 확인했다.

## 2. 계약 정의

**보고 지연 L = 피킹 어택이 출력에 도착하는 시각 = STFT 대역의 분석 창**(48 kHz 480 샘플 = 10.0 ms, 44.1 kHz 440, 96 kHz 960).

- 보장: 감지된 피킹 어택은 저역·고역 모두 L ± 작은 오차로 도착한다.
- 보장하지 않음: 지속 구간과 피킹 없는 음 변화(레가토, 해머온)의 도착 시각. 이 범위는 §5에 한계값으로 적는다.
- 근거: 템포 그리드에 대한 체감 타이밍과 원음·변환음 블렌드의 어택 정렬은 어택이 결정한다. 지속음에는 시간 기준점이 없다.

## 3. 구현 (연구, probe 모드 39 `AL10RA-800-L10`)

`HybridLowBandPitch::setAttackLatency(leadMs)`:

- `latency()`가 L(STFT 창)을 반환한다. 이전에는 −1(보고 안 함)이었다.
- 저역 앵커를 **양방향 모두** `(L + lead − τ) · ratio − lead`로 둔다(`CorrelationPitch::setAnchorInputDelay`).
  - τ = LR4 크로스오버의 DC 군지연 `2√2 / (2π fc)`이다(800 Hz: 0.56 ms).
  - 읽기 헤드가 현재에서 `1 − ratio` 속도로 움직이므로, 어택은 `τ + (앵커 + lead) / ratio` 뒤에 나온다. 다운시프트·업시프트 모두 같은 식이다.
  - 이전 AL10RA는 업시프트를 "10 ms 상한"으로만 다뤄 어택이 5–7 ms로 일렀다.
- lead는 측정으로 정했다.
  - lead = 0이면 어택이 −12에서 11.4 ms, −2에서 10.2 ms로 1/ratio에 비례해 남았다.
  - lead = 1.4 ms에서 모든 반음이 8.6 ms로 평평해졌고, 목표에 lead를 더해 10 ms에 맞췄다.
- 앵커는 [최소 지연 + 가드, 최대 지연 − 가드]로 제한한다. +12의 앵커는 18.8 ms로 40 ms 한도 안이다.

lead sweep(B0 / E2 / E2 파워코드 / A3 / E2 재피킹, 저역 어택 ms):

| 반음 | lead 0 | lead 1.4, 목표 L | **lead 1.4, 목표 L + 1.4** |
|---:|---|---|---|
| −12 | 11.4–12.1 | 8.6–9.3 | **10.0–10.7** |
| −2 | 10.2–10.3 | 8.6–8.8 | **10.0–10.2** |
| +2 | 9.7–9.8 | 8.5–8.6 | **9.9–10.0** |
| +12 | 8.8–9.2 | 8.1–8.4 | **9.5–9.8** |

## 4. 측정 (`Tools/transpose_latency_contract.py`, `latency_contract_48k.json`)

이벤트마다 도착 지연에서 보고 지연을 뺀 오차를 쟀다. TIGHT는 480 샘플을 보고하고, AL10RA-800은 보고하지 않아(−1) 10 ms를 기준으로 쓴다.

- **피킹**: 프로토콜 소재 7종과 팜뮤트 16분음표의 각 피킹. 150 Hz 아래 첫 교차 지연을 쓴다.
- **레가토 / 해머온**: E2·A2 지속음이 피킹 없이 1–2반음 바뀐다. 해머온은 +6 dB, 2 ms 범프를 더한다.
  - 도착 시점은 새 음 레벨이 이전 음을 넘는 시점이다.
  - 레벨은 120 ms Hann 복조로, 서로 18 Hz 넘게 떨어진 배음 1–10만 합해 구한다.
  - 자체 검증: 입력을 정확히 10 / 30 ms 늦춘 신호에서 모든 이벤트가 10.00 / 30.00 ms로 복원된다. 처음에 음 변화를 누적하지 않던 생성기 버그를 이 검증으로 찾아 고쳤다.

| 이벤트 (반음 8개) | TIGHT | AL10RA-800 | **AL10RA-800-L10** |
|---|---|---|---|
| 피킹 216건: 오차 중앙값 / 범위 | +2.0 / −4.8 … +8.9 ms | −2.5 / −5.6 … −0.8 ms | **+0.06 / −0.5 … +2.3 ms** |
| 피킹 ±1 ms 이내 | 31 % | 9 % | **74 %** (단발 피킹만은 100 %, ±0.7 ms) |
| 레가토 72건: 중앙값 / 범위 | 측정 불가 | +12.0 / −4.5 … +29.6 ms | +12.6 / −3.9 … +28.9 ms |
| 해머온 72건: 중앙값 / 범위 | 측정 불가 | +11.7 / −18.5 … +28.5 ms | +13.1 / −15.8 … +28.6 ms |

- 피킹 오차가 큰 쪽은 팜뮤트 16분음표다(최대 +2.3 ms, 125 ms마다 재피킹). 단발 피킹 소재 7종은 −0.5 … +0.7 ms다.
- TIGHT는 10 ms를 보고하지만, 150 Hz 아래 어택은 평균 2 ms, 최대 9 ms 늦다(짧은 창의 저역 번짐). TIGHT의 레가토 값은 저음 음정 오류(60–370 cents) 때문에 레벨 비교가 성립하지 않아 쓰지 않는다.
- 레가토·해머온은 **계약 밖**이다.
  - 감지가 재정렬을 걸지 않으면 새 음은 지속 구간 읽기 위치에서 나온다: 다운시프트 +14 … +29 ms, 업시프트 −4 … +13 ms.
  - 해머온의 음수(최대 −16 ms)는 범프가 두 음 레벨 비교를 흔든 측정 편향일 수 있다. 확인하지 않았다.
- 음질 영향: 화음 지표(E2 파워코드, 오픈 E, A3 파워코드, C4 장3화음, E2·B0 단음)가 AL10RA-800과 0.1 dB 이내로 같다(`chord_l10_48k.json`).

## 5. 보장 범위와 한계 (48 kHz, AL10RA-800-L10)

| 성분 | 보고 지연 L = 10.0 ms 대비 도착 |
|---|---|
| 감지된 피킹 어택 | −0.5 … +2.3 ms (단발 피킹 ±0.7 ms) |
| 지속 구간 저역(800 Hz 아래) | 읽기 지연 2 … 40 ms + τ 0.56 ms ⇒ **최대 7.4 ms 이르고, 최대 30.6 ms 늦음** |
| 지속 구간 고역(800 Hz 위) | L 고정 |
| 피킹 없는 음 변화 | −4 … +29 ms (측정) |

## 6. 제품 통합 설계 (미구현)

현재 `spectralforge::Transposer`(`Source/GlobalDSP.h`)의 구조를 그대로 쓴다.

1. 네 번째 모드로 하이브리드 인스턴스를 `prepare()`에서 만든다(할당은 prepare에서만).
   - `latency()` = L. `dryDelay`는 L로 맞추고 `maxLatency`에 포함한다.
   - 모드 전환은 기존 `setMode()` 경로(새 인스턴스 reset, 원음 경로 지연 재설정, wet 0에서 다시 페이드)를 쓴다.
2. 0반음·바이패스는 기존 `wet` / `engage` 15 ms 크로스페이드로 처리한다. 하이브리드 내부의 "0반음이면 원음 그대로" 경로는 쓰지 않는다. 원음 경로가 L만큼 늦으므로 이전에 남긴 "즉시 원음 전환" 과제가 함께 해결된다.
3. 호스트 보고는 `PluginProcessor`의 기존 `setLatencySamples(... + preFX.transpose.latency())` 경로를 그대로 탄다. 모드를 바꾸면 보고 지연이 바뀐다(CLASSIC 43 ms ↔ 10 ms). 기존 모드 전환과 같은 동작이다.
4. 제품에는 연구 사본 `PhaseLockPitch`가 아니라 `spectralforge::PolyPitch`를 쓴다(위상 고정은 기각됨). 하이브리드 내부 디노멀 방지(`ScopedNoDenormals`)는 유지한다.
5. 확인할 것:
   - 실제 DAW 왕복(원음·변환음을 같이 녹음해 어택 정렬 확인)
   - 오프라인 바운스와 실시간 재생의 일치
   - 샘플레이트 변경 시 L 재계산
   - Windows 호스트 CPU
   - `TransposeNext` 회귀 테스트에 하이브리드 블록 크기 불변성·무할당 테스트 추가

## 7. 남은 연구

- **레가토 재정렬**: 피킹 없는 음정 변화를 감지해 재정렬을 거는 방법. 예: 상관 탐색의 주기 추정 변화, 저역 LPC 잔차(#128의 LPC onset 확인과 연계). 오검출은 지속음 떨림(warble)을 만들 수 있어 비브라토·벤드에서 재정렬이 일어나지 않는지 함께 봐야 한다.
- 실제 DI와 §5 블라인드 청음.
