# Transpose 하이브리드 고정 지연 보고 설계 — 2026-10-23 KST

연구 단계 설계다. 대상은 `Tools/TransposeNext/HybridLowBandPitch.h`의 AL10RA-800(800 Hz LR4, 아래는 onset 재정렬 시간영역, 위는 10 ms STFT)이다. 제품 코드(`Source/`)는 바꾸지 않았다. 측정은 합성 소재뿐이며, 실제 DAW 왕복 지연·DI·청음은 하지 않았다. 배경 수치는 `docs/TRANSPOSE_SYNTHETIC_EVIDENCE_20261023.md`에 있다.

## 1. 문제

호스트 PDC는 플러그인이 보고한 고정 지연 L만큼 출력을 앞당긴다. STFT 모드(CLASSIC / LOW-LAT / TIGHT)는 모든 성분이 분석 창 길이만큼 늦어 L이 하나로 정해진다.

시간영역 읽기 헤드는 그렇지 않다. 다운시프트는 지연이 2 ms에서 40 ms 쪽으로 늘고, 업시프트는 줄어들다가 스플라이스로 되돌아간다. 이 지속 구간 지연은 원리상 고정할 수 없다. 앞 문서에서 지연 상한을 최저음 한 주기 아래로 줄이면 음정이 원래대로 돌아가는 것을 확인했다.

## 2. 계약 정의

**보고 지연 L = 피킹 어택이 출력에 도착하는 시각 = STFT 대역의 분석 창**(48 kHz 480 샘플 = 10.0 ms, 44.1 kHz 440, 96 kHz 960).

- 보장: 감지된 피킹 어택은 저역·고역 모두 L ± 작은 오차로 도착한다.
- 보장하지 않음: 지속 구간과 피킹 없는 음 변화(레가토, 해머온)의 도착 시각. 이 범위는 §5에 한계값으로 적는다.
- 근거: 템포 그리드에 대한 체감 타이밍과 원음·변환음 블렌드의 어택 정렬은 어택이 결정한다. 지속음에는 시간 기준점이 없다.

## 3. 구현 (연구, probe 모드 39 `AL10RA-800-L10`)

`HybridLowBandPitch::setAttackLatency(leadMs)`:

- `latency()`가 L(STFT 창)을 반환한다. 이전에는 −1(보고 안 함)이었다.
- 저역 앵커를 **양방향 모두** `(L + lead − τ) · ratio − lead`로 둔다(`CorrelationPitch::setAnchorInputDelay`).
  - τ = LR4 크로스오버의 DC 군지연 `2√2 / (2π fc)`이다(800 Hz: 0.56 ms).
  - 읽기 헤드가 현재에서 `1 − ratio` 속도로 움직이므로, 어택은 `τ + (앵커 + lead) / ratio` 뒤에 나온다. 다운시프트·업시프트 모두 같은 식이다.
  - 이전 AL10RA는 업시프트를 "10 ms 상한"으로만 다뤄 어택이 5–7 ms로 일렀다.
- lead는 측정으로 정했다.
  - lead = 0이면 어택이 −12에서 11.4 ms, −2에서 10.2 ms로 1/ratio에 비례해 남았다.
  - lead = 1.4 ms에서 모든 반음이 8.6 ms로 평평해졌고, 목표에 lead를 더해 10 ms에 맞췄다.
- 앵커는 [최소 지연 + 가드, 최대 지연 − 가드]로 제한한다. +12의 앵커는 18.8 ms로 40 ms 한도 안이다.

lead sweep(B0 / E2 / E2 파워코드 / A3 / E2 재피킹, 저역 어택 ms):

| 반음 | lead 0 | lead 1.4, 목표 L | **lead 1.4, 목표 L + 1.4** |
|---:|---|---|---|
| −12 | 11.4–12.1 | 8.6–9.3 | **10.0–10.7** |
| −2 | 10.2–10.3 | 8.6–8.8 | **10.0–10.2** |
| +2 | 9.7–9.8 | 8.5–8.6 | **9.9–10.0** |
| +12 | 8.8–9.2 | 8.1–8.4 | **9.5–9.8** |

## 4. 측정 (`Tools/transpose_latency_contract.py`, `latency_contract_48k.json`)

이벤트마다 도착 지연에서 보고 지연을 뺀 오차를 쟀다. TIGHT는 480 샘플을 보고하고, AL10RA-800은 보고하지 않아(−1) 10 ms를 기준으로 쓴다.

- **피킹**: 프로토콜 소재 7종과 팜뮤트 16분음표의 각 피킹. 150 Hz 아래 첫 교차 지연을 쓴다.
- **레가토 / 해머온**: E2·A2 지속음이 피킹 없이 1–2반음 바뀐다. 해머온은 +6 dB, 2 ms 범프를 더한다.
  - 도착 시점은 새 음 레벨이 60–150 ms 뒤 레벨의 50 %에 처음 닿는 시점이다(입력·출력 차).
  - 레벨은 120 ms Hann 복조로, 출력 주파수에서 상대 음의 배음과 18 Hz 넘게 떨어진 배음 1–10만 합해 구한다.
  - 처음 지표(이전 음·새 음 레벨 교차, 입력 주파수 간격)는 §7의 두 가지 이유로 바꿨다. 아래 표는 바꾼 지표 값이다(`latency_contract_legato_48k.json`의 모드 39). `latency_contract_48k.json`의 레가토·해머온 행은 처음 지표 값이다.
  - 자체 검증: 입력을 정확히 10 / 30 ms 늦춘 신호에서 10.1–10.2 / 30.3–30.5 ms로 복원된다(감쇠에 따른 편향). 처음에 음 변화를 누적하지 않던 생성기 버그를 이 검증으로 찾아 고쳤다.

| 이벤트 (반음 8개) | TIGHT | AL10RA-800 | **AL10RA-800-L10** |
|---|---|---|---|
| 피킹 216건: 오차 중앙값 / 범위 | +2.0 / −4.8 … +8.9 ms | −2.5 / −5.6 … −0.8 ms | **+0.06 / −0.5 … +2.3 ms** |
| 피킹 ±1 ms 이내 | 31 % | 9 % | **74 %** (팜뮤트 제외 100 %, ±0.7 ms) |
| 레가토 72건: 중앙값 / 범위 | 측정 불가 | (처음 지표) +12.0 / −4.5 … +29.6 ms | +13.0 / −4.3 … +31.4 ms (69건) |
| 해머온 72건: 중앙값 / 범위 | 측정 불가 | (처음 지표) +11.7 / −18.5 … +28.5 ms | +15.8 / −17.6 … +32.4 ms (69건) |

- 피킹 216건 = 단발 소재 5종 40건 + 재피킹 2종의 첫 피킹 16건 + 팜뮤트 160건. 재피킹 2종의 두 번째 이후 피킹 48건은 세 모드 모두 측정에서 빠졌다(직전 음 꼬리가 커서 '직전 30 ms의 2배' 기준을 넘는 지점이 없음).
- 피킹 오차가 큰 쪽은 팜뮤트 16분음표다(최대 +2.3 ms, 125 ms마다 재피킹). 나머지 피킹은 −0.5 … +0.7 ms다.
- TIGHT는 10 ms를 보고하지만, 150 Hz 아래 어택은 평균 2 ms, 최대 9 ms 늦다(짧은 창의 저역 번짐). TIGHT의 레가토 값은 저음 음정 오류(60–370 cents) 때문에 레벨 비교가 성립하지 않아 쓰지 않는다.
- 레가토·해머온은 **계약 밖**이다.
  - 감지가 재정렬을 걸지 않으면 새 음은 지속 구간 읽기 위치에서 나온다. 레가토는 다운시프트 +6 … +31 ms, 업시프트 −4 … +17 ms다.
  - 해머온은 다운시프트 −18 … +29 ms, 업시프트 −4 … +32 ms다. 음수 쪽은 범프가 측정을 흔든 편향일 수 있다. 확인하지 않았다(§7).
- 음질 영향: 화음 지표(E2 파워코드, 오픈 E, A3 파워코드, C4 장3화음, E2·B0 단음)가 AL10RA-800과 0.1 dB 이내로 같다(`chord_l10_48k.json`).

## 5. 보장 범위와 한계 (48 kHz, AL10RA-800-L10)

| 성분 | 보고 지연 L = 10.0 ms 대비 도착 |
|---|---|
| 감지된 피킹 어택 | −0.5 … +2.3 ms (팜뮤트 제외 ±0.7 ms) |
| 지속 구간 저역(800 Hz 아래) | 읽기 지연 2 … 40 ms + τ 0.56 ms ⇒ **최대 7.4 ms 이르고, 최대 30.6 ms 늦음** |
| 지속 구간 고역(800 Hz 위) | L 고정 |
| 피킹 없는 음 변화 | 레가토 −4 … +31 ms, 해머온 −18 … +32 ms (측정, 레가토 재정렬 없음) |

제품(probe 모드 45: 레가토 재정렬 + 위상 정렬 + 10 ms 안정 가드)에서 피킹 없는 음 변화는 읽기 헤드 기준으로 레가토 −6.3 … +3.2 ms(±5 ms 이내 90 %), 해머온 −5.8 … +3.2 ms(92 %)다(§7.4, §7.5). 지속 구간 저역은 방향에 따라 다르다(§7.6).
- 다운시프트: 읽기 지연이 약 14–40 ms에 머문다. 평균 |지연 − (L − τ)|는 18–25 ms다. 줄이는 연구 옵션이 있지만 제품에는 넣지 않았다(§7.6).
- 업시프트: 읽기 지연은 2–27 ms, 평균 3–7 ms다.

## 6. 제품 통합 (2026-10-24 구현, 합성 검증만)

구현: `Source/HybridTranspose.h`(`spectralforge::hybrid::HybridTransposer`), Transposer 모드 3 "HYBRID".
- 동작은 probe 모드 45와 같다: 800 Hz 크로스오버, 레가토 재정렬, 레가토에서만 ±2.5 ms 위상 정렬, 10 ms 안정 가드(§7.5). 통합 당시에는 모드 41이었다. `Tests/PitchRegressionTests.cpp`가 44.1/48/96 kHz × −12·−5·−2·+2·+7·+12반음(E2 단음·파워코드·±100 c 비브라토)에서 연구 사본과 비트 단위로 같은지 확인한다.
- 보고 지연은 TIGHT와 같은 10 ms 창이다. 8–192 kHz, 1–2채널만 지원하고, 그 밖(예: 384 kHz)에서는 TIGHT로 대체된다(`StabilityTests`).
- 0반음·바이패스에서는 변환 엔진을 돌리지 않고 L만큼 지연된 원음을 낸다. 필터와 레가토 감지기는 계속 입력을 받으므로 다시 켜질 때 상태가 이어진다.
- 블록 크기 불변성: 처음 구현은 블록이 끝날 때 한 번만 레가토 감지기에 피킹을 알렸다(`notePick`). 그래서 피킹 뒤 감지기 상태가 블록 경계에 따라 달라졌다. 다시 피킹한 E2에서 48 kHz 블록 512, 44.1 kHz 블록 500이 블록 128과 최대 2.4e-3 달랐다. 단일 피킹·고정 128 블록만 보던 기존 테스트는 이를 놓쳤고, 프로세서 수준 바운스 비교에서 드러났다. 수정 방법: 블록을 감지기의 1 ms 갱신 직전마다 잘라 처리한다. `notePick`은 갱신 상태만 바꾸므로 샘플 단위로 번갈아 처리한 것과 정확히 같다. 연구 사본(`HybridLowBandPitch.h`)도 같이 고쳤다. 블록 128에서는 이 재료(0.3 s·0.125 s 재피킹, 44.1/48/96 kHz, −5/+7)의 출력이 수정 전과 비트 단위로 같아서, 앞 절의 증거 수치는 그대로다. CPU 차이는 측정 잡음 안이다(20 s 오디오 기준 약 1.45 s, 48 kHz 스테레오). 테스트는 블록 1·32·100·128·500·512·1024와 불규칙 블록에서, 화음과 재피킹 단음으로 44.1/48/96 kHz를 본다. 블록 끝 처리로 되돌리면 실패한다.
- `StabilityTests`의 `pitchNoAllocation`: 모드 0–3을 처리 도중 바꾸고 반음·바이패스·블록 크기(1–1024)를 바꿔도 `prepare()` 이후 할당이 없다(44.1–192 kHz, 모노·스테레오). `operator new`와, glibc에서는 `malloc`/`calloc`/`realloc`까지 센다(JUCE `HeapBlock`은 `malloc`을 직접 쓴다). `process`에 `HeapBlock`을 넣으면 실패하는 것을 확인했다. 48 → 96 kHz로 다시 prepare하면 HYBRID 지연도 96 kHz 10 ms 창으로 바뀐다.
- `IntegratedProcessorTests`의 `transposeQualityLatency`(빠른 실행: `--transpose-quality-only`): 실제 `ChimeraProcessor`에서 품질을 3→0→1→2→3으로 바꾸면 다음 콜백에서 호스트 보고 지연이 바뀐다(44.1/48/96 kHz, 페달보드 켬·끔). HYBRID 상태를 저장·복원하면 첫 콜백 전에 10 ms가 보고된다. 복원 경로를 0–2로 제한하면 실패하는 것을 확인했다. 실제 호스트의 PDC 동작은 확인하지 않았다. 오프라인 바운스와 실시간 재생은 블록 크기만 다르다. 이는 위 블록 크기 불변성 테스트(프로세서 수준 포함)로 확인했다. 실제 DAW 왕복, Windows CPU, DI 녹음·블라인드 청취는 아직 하지 않았다.

아래는 통합 전에 쓴 설계 메모다.

현재 `spectralforge::Transposer`(`Source/GlobalDSP.h`)의 구조를 그대로 쓴다.

1. 네 번째 모드로 하이브리드 인스턴스를 `prepare()`에서 만든다(할당은 prepare에서만).
   - `latency()` = L. `dryDelay`는 L로 맞추고 `maxLatency`에 포함한다.
   - 모드 전환은 기존 `setMode()` 경로(새 인스턴스 reset, 원음 경로 지연 재설정, wet 0에서 다시 페이드)를 쓴다.
2. 0반음·바이패스는 기존 `wet` / `engage` 15 ms 크로스페이드로 처리한다. 하이브리드 내부의 "0반음이면 원음 그대로" 경로는 쓰지 않는다. 원음 경로가 L만큼 늦으므로 이전에 남긴 "즉시 원음 전환" 과제가 함께 해결된다.
3. 호스트 보고는 `PluginProcessor`의 기존 `setLatencySamples(... + preFX.transpose.latency())` 경로를 그대로 탄다. 모드를 바꾸면 보고 지연이 바뀐다(CLASSIC 43 ms ↔ 10 ms). 기존 모드 전환과 같은 동작이다.
4. 제품에는 연구 사본 `PhaseLockPitch`가 아니라 `spectralforge::PolyPitch`를 쓴다(위상 고정은 기각됨). 하이브리드 내부 디노멀 방지(`ScopedNoDenormals`)는 유지한다.
5. 확인할 것:
   - 실제 DAW 왕복(원음·변환음을 같이 녹음해 어택 정렬 확인)
   - 오프라인 바운스와 실시간 재생의 일치
   - 샘플레이트 변경 시 L 재계산
   - Windows 호스트 CPU
   - `TransposeNext` 회귀 테스트에 하이브리드 블록 크기 불변성·무할당 테스트 추가

## 7. 레가토 재정렬 연구 (probe 모드 40, 진행 중 — 채택 안 함)

`Tools/TransposeNext/LegatoDetector.h`가 저역 입력에서 피킹 없는 음정 변화를 감지해 외부 재정렬을 건다. 감지가 늦은 만큼은 앵커에서 보상한다.

**감지**
- 주기 예측 오차 `e = Σ(x[t] − x[t−P])² / Σ(x[t]² + x[t−P]²)`(최근 4 ms)를 쓴다. 과거만 보므로 주기 길이와 무관하게 수 ms 안에 반응한다.
- 입력을 미분해 고차 배음 비중을 높인다. 음정이 Δf 바뀌면 배음 k의 위상 차가 k·Δf 속도로 커지기 때문이다.
- P는 1 ms마다 ±4 % 안에서 다시 맞춘다. 비브라토·벤드는 이 범위 안에서 따라간다.
- 이벤트 조건:
  - 잠금(e < 0.02)이 10 ms 이상 유지된 뒤
  - e가 기준값의 6배를 넘고 5 ms 안에 0.06 넘게 오를 때
  - 30 ms 쿨다운
- 적용 범위: 주기 20 ms 이하(기음 50 Hz 이상). 45 Hz 2차 저역 통과 에너지가 20 %를 넘으면 잠그지 않는다. B0·E1은 범위 밖이다(가드가 없으면 B0 파워코드에서 3 s에 9회 오검출).

**감지 지연 보상**
- 변화 시점은 마지막으로 맞던 갱신 시각으로 추정한다(age).
- 앵커에 `(1 − ratio) × age`를 더한다. 읽기 헤드 식에서 유도한 `D0 = rL − rτ + (1 − r)·age`이고, age가 L보다 작으면 늦게 감지해도 L에 도착한다.

**측정 지표 보정 2건**

- 배음 선택 간격(18 Hz)은 출력 주파수 기준으로 적용한다. 다운시프트는 간격이 ratio배로 줄어, 입력 기준으로 고르면 이전 음이 새로 샜다(−12 출력의 0.21 바닥).

### 7.1 해머온 측정 편향 분리

§7의 해머온 이른 값(최대 −25 ms)이 측정 탓인지 엔진 탓인지 단계별로 분리했다.

1. **레벨 지표 자체가 해머온에서 편향된다.**
   - 이상적 출력(f0 × ratio로 재합성 후 정확히 10 ms 지연)을 입력 기준으로 재면 레가토 −3.3 … +2.9 ms, 해머온 −9.5 … +13.6 ms가 나온다.
   - 범프가 새 음 시작부 레벨을 키우고, 반음마다 고르는 배음 집합이 달라 입력·출력에서 효과가 다르다.
   - 엔벨로프로 나누는 평탄화는 해머온 편향을 줄이지만 저음 파형을 왜곡해 레가토를 −3.0 … +7.1 ms로 나쁘게 해 버렸다.
2. **이상적 출력 기준**: 같은 지표로 엔진 출력과 "보고 지연만큼 늦춘 이상적 출력"을 재서 뺀다. 순수 지연 검증에서 0 / +10 / +20 ms를 ±0.5 ms로 복원한다. 그런데 엔진 출력에는 여전히 −34 ms가 나왔다.
3. **주기 단위 확인**:
   - 한 사례(E2 해머온, −5반음)를 영교차 주기로 보면, 재정렬 순간 30 ms짜리 불규칙 주기가 하나 생긴다. 읽기 헤드가 주기 중간에 점프한 흔적이다.
   - 그 뒤 새 주기는 이상적 출력보다 +2.4 ms(레가토 +0.8 ms)에서 시작한다. 레벨 지표가 점프의 광대역 성분을 새 음으로 읽은 것이다.
   - 주기 지표는 파형 위상이 다르면 한 주기(12–22 ms) 단위로 양자화된다. 주기 안 보간을 넣어도, 엔진처럼 리샘플링한 시험 신호에서 −15.6 … +11.0 ms가 남는다.
4. **순간 주파수 지표**:
   - 기음만 영위상 FFT 대역통과하고 해석 신호 순간 주파수가 중간값을 지나 10 ms 유지되는 시점을 쓴다.
   - 리샘플링 시험 신호(점프 없음)에서 레가토 ±1.4 ms, 해머온 −4.1 … +4.7 ms로 정확하다.
   - 그러나 엔진 출력에서는 재정렬이 일어나는 이벤트에 −20 … −37 ms가 남았다. 저역 읽기 지연 하한(2 ms + τ)상 보고 지연보다 7.4 ms 넘게 이른 도착은 불가능하므로, 이것도 측정 오염이다.
5. **엔진 내부 참값**:
   - 프로브 옵션 `delays=<path>`가 저역 읽기 지연 D(t)를 샘플마다 내보낸다.
   - 출력 시각 t가 읽는 입력 위치 `t − D(t)`가 저역 입력의 변화 시점(변화 + τ)을 처음 넘는 t를 도착으로 본다. 신호를 보지 않으므로 재정렬 불연속에 오염되지 않는다.
   - `transpose_latency_contract.py`의 `read_head_error_ms`가 이 값이다.

참 도착 오차 (저역 읽기 헤드, 보고 지연 10 ms 대비; `latency_contract_legato_48k.json`):

| 이벤트 72건씩 | 모드 39 (재정렬 없음) | **모드 40 (레가토 재정렬)** |
|---|---|---|
| 해머온 중앙값 / 범위 | +1.3 / −7.0 … +29.3 ms | **0.0 / −4.8 … +2.4 ms** |
| 해머온 ±2 / ±5 ms 이내 | 32 % / 51 % | **96 % / 100 %** |
| 레가토 중앙값 / 범위 | +9.5 / −7.0 … +29.3 ms | **0.0 / −5.9 … +29.3 ms** |
| 레가토 ±2 / ±5 ms 이내 | 15 % / 36 % | **43 % / 68 %** |

- 순간 주파수 지표와 참값의 차이는 재정렬이 있는 조건에서 −35 … +35 ms다(모드 40 해머온은 ±3 ms 이내가 12 %).
- 결론: §7의 해머온 이른 값과 "+12에서 체계적으로 늦음"은 **측정 오염**이었다. 참값으로는 +12 해머온도 +0.4 … +2.4 ms다.
- 남는 실제 문제는 두 가지다.
  - **순수 레가토 1반음 변화를 놓친다.** 늦은 이벤트 19건이 모두 순수 레가토이고, 그중 1반음 변화가 +12 … +29 ms다(E2 상행 1.6 s, E2 하행 1.0 s, A2 상행 2.2 s). 2반음 변화와 해머온은 모두 감지된다.
  - **재정렬 점프가 주기 중간에서 일어나 불규칙 주기를 만든다**(모드 40: 레가토 25 / 72, 해머온 44 / 72 이벤트). 청감상 끊김 후보다.
- 참값은 저역 읽기 헤드 기준이다. τ는 LR4의 DC 군지연 근사다. 800 Hz 위 STFT 대역은 고정 10 ms라 따로 재지 않았다.

### 7.2 재정렬 점프 위상 맞추기 (probe 모드 41–43)

**제약**
- 두 읽기 위치는 같은 속도로 움직이므로 위상차가 시간에 따라 변하지 않는다. 점프 시점이 아니라 목적지 D를 옮겨야 위상이 맞는다.
- 완전히 맞추려면 최대 ±반 주기(E2 ±6 ms, B0 ±16 ms)가 필요하고, 도착이 그만큼 / ratio 흔들린다.

**방법**
- `CorrelationPitch::phaseAligned`가 재정렬 목표 ±W 안에서, 읽기 헤드가 방금 재생한 파형과 가장 맞는 위치(스플라이스 비용 `integerCost`)를 고른다.
- 모드 41: W = 2.5 ms, 레가토 재정렬만
- 모드 42: W = 2.5 ms, 피킹 재정렬에도
- 모드 43: W = 6 ms, 피킹 재정렬에도

- 점프 불연속: 1 kHz 저역 통과 출력의 2차 차분 피크(점프 ±2.5 ms) / 10–30 ms 전 중앙값. 점프가 없는 이상적 출력은 중앙값 6.0–6.3 dB, p90 7.5–7.9 dB다.

**판별 특징** (`legfeat` 분석, Python 재현)

  - 1반음 순수 레가토 감지 — §7.4에서 해결(주기 이동 경로)
  - 극단적 비브라토·빠른 벤드에서의 재정렬 — §7.5에서 해결(10 ms 안정 가드, 제품 적용)
  - 남은 것: 실제 DI 레가토 연주로 확인
  - 재정렬 위상 맞추기는 레가토에만 ±2.5 ms로 쓴다(모드 41, §7.2).

### 7.5 비브라토·빠른 벤드 가드: 직전 안정 조건 (probe 모드 44–46, 제품 = 45)

**문제 측정** (`Tools/TransposeEvidence/legato_modulation_probe.py`, `legato_modulation_48k.txt`)
- 소재: 감쇠가 느린 비조화 현(E2, A2)에 알려진 cents 궤적(비브라토, 벤드, 벤드 후 복귀)을 건 것.
- 지표: 출력 기본음의 사이클마다 주파수를 입력 궤적 × 비율(지연은 0–45 ms에서 맞춤)과 비교한다. 읽기 헤드가 사이클 중간에서 점프하면 길거나 짧은 사이클이 하나 남는다.
- 지표 바닥(입력 자체를 채점): 5 cents 미만. 30 ms 벤드만 최대 47 cents다(벤드가 E2 약 2.5주기 안에 끝남).

| 소재 (−12/−5/+2/+12 중 최악) | 레가토 재정렬 없음 (39) | 가드 없음 (41) | **가드 10 ms (45)** |
|---|---|---|---|
| E2 ±100 c 7 Hz: 이벤트 / 최악 / >50 c 비율 | 0 / 102 c / 8 % | 29 / 648 c / 21 % | **1 / 338 c / 8 %** |
| A2 ±100 c 7 Hz | 0 / 83 c / 8 % | 14 / 468 c / 21 % | **1 / 214 c / 8 %** |
| E2 벤드 200 c / 50 ms | 0 / 124 c | 2 / 557 c | **0 / 124 c** |
| E2 벤드·복귀 200 c / 50 ms ×2 | 0 / 48 c | 2 / 661 c | **0 / 48 c** |
| ±20·±50 c 비브라토, 100 ms 벤드, 30 ms 100 c 벤드 | 0 | 0 (39와 같음) | 0 (같음) |

- 넓은 비브라토와 빠른 벤드에서는 재정렬이 사이클 오차를 키웠다. 재정렬하지 않는 편이 낫다.
- TIGHT는 이 저역 소재에서 300–800 cents를 읽는다(알려진 저역 한계, 참고용).

**가드** (`LegatoDetector::setSteadyGuard`)
- 레가토 단계는 바로 직전까지 안정된 음(5 ms 주기 이동 0.3 % 미만)을 남긴다. ±100 c 비브라토에서 마지막 안정 맞춤은 약 30 ms 전 비브라토 꼭짓점이다.
- 두 경로 모두 "변화 직전 G ms 안에 안정 맞춤이 있었을 것"을 요구한다.
  - 오차 경로: 마지막 안정 맞춤이 마지막 정상 맞춤보다 G 이내
  - 주기 이동 경로: 마지막 안정 맞춤이 G 이내
- 막힌 후보는 버리기만 한다(쿨다운 없음). 그래서 오검출은 늘 수 없다.

**레가토 감지 유지** (`legato_vibrato_steps_probe.py`, `legato_vibrato_steps_48k.txt`; 읽기 헤드 기준 도착 − 보고 지연, 종류마다 72 이벤트)
- G = 10 ms(모드 45)는 모드 41과 모든 값이 같다. 순수 레가토와 해머온 모두, 비브라토 없음 / ±20 c 5.5 Hz / ±50 c 6 Hz 위에서의 단계에서 확인했다. 예: 순수 레가토 −6.3 … +3.2 ms, ±5 ms 이내 90 %.
- G = 6 ms(모드 44)는 비브라토 위 레가토 일부를 놓친다(최대 +29.7 ms, ±5 ms 이내 76 %).
- G = 15 ms(모드 46)는 비브라토·벤드 이벤트를 더 남긴다(E2 ±100 c 2회, 50 ms 벤드 1회).
- 6·15 ms 값은 같은 두 스크립트를 `--modes 44,46`으로 돌린 탐색 결과다. 결과 파일은 남기지 않았다.

**판정**: G = 10 ms를 제품(`HybridTransposer`)에 넣었다.
- `Tests/PitchRegressionTests.cpp`의 비트 일치 비교 대상은 모드 45다. 가드가 실제로 동작하는 ±100 c 7 Hz 비브라토 소재를 추가했고, 제품에서 가드를 끄면 실패하는 것을 확인했다.
- 남은 것:
  - ±100 c 비브라토 시작 직후의 1회 재정렬(안정 음에서 막 움직이기 시작한 순간은 레가토 단계와 구별되지 않음)
  - DI 연주와 청감 확인

### 7.6 지속 구간 저역 지연: 경계 낮추기와 중심 맞추기 (probe 모드 47–54, 제품 미적용)

`Tools/TransposeEvidence/bound_sweep_probe.py`는 다음 네 가지를 함께 잰다.
- 지속 구간 읽기 지연 범위와 스플라이스 빈도(E2, A2, E2 파워코드)
- 피킹·레가토 계약(`transpose_latency_contract`)
- 화음 지표(`transpose_chord_metric`)
- 비브라토·벤드 사이클 오차(`legato_modulation_probe`)

**원인**
- 다운시프트에서는 읽기 지연이 (1 − 비율)로 늘다가 경계(40 ms − guard)에 닿아야 스플라이스한다.
- 스플라이스는 가장 잘 맞는 지점으로 되돌아가는데, 대개 입력 주기 1–2개(E2 12.1 ms)만큼이다.
- 그래서 지연이 [경계 − 점프, 경계]에 머문다. 저역이 10 ms인 고역보다 평균 22–25 ms 늦는 것은 퍼짐이라기보다 거의 일정한 치우침이다.
- 업시프트는 영향이 없다(2–15 ms를 순환).

**경계 낮추기** (모드 47 = 30 ms, 48 = 25 ms; `bound_sweep_48k.txt`)
- 다운시프트 평균 |지연|은 25 → 16 / 11 ms로 줄고, 피킹 최대는 +2.3 → +1.2 / +1.1 ms로 좋아진다.
- 그러나 화음이 망가진다.
  - D2 파워코드: spurious −32.5 → −0.7 dB(30 ms에서 이미 13개 음정 어긋남)
  - B0 단음: −33.6 → −1.3 / −0.1 dB
  - E2 파워코드: 25 ms에서 −1.0 dB
- 주기가 긴 저음과 화음은 넓은 창이 있어야 깨끗한 스플라이스 지점이 생긴다. **기각.**

**중심 맞추기** (`CorrelationPitch::setSustainCentre`, 경계는 40 ms 유지)
- 다운시프트 지연이 L − τ를 넘으면 1 ms마다 스플라이스를 시도한다.
- 최적 후보의 비용이 한계 c 이하일 때만 받아들인다. 아니면 계속 늘다가 경계에서 기존처럼 강제 스플라이스한다.
- c = .05 / .1 / .2(모드 49–51; `centre_sweep_48k`, 증거로 남기지 않음): 지연은 좋아졌다(E2 평균 3 ms). 그러나 품질이 크게 나빠져 기각했다.
  - E2 단음 spurious −35.9 → −11 dB
  - ±20 c 비브라토 사이클 중앙값 1.4 → 26–90 cents
  - c가 느슨해서 주기 배수가 아닌 지점에서 잘랐다.
- 더 엄격한 c(.01 / .003 / .001, 모드 52–54; `centre_strict_48k.txt`): 지연 이득은 그대로이고 품질 손실은 작아졌다. c = .001(모드 54)과 제품(모드 45)을 비교하면 아래와 같다.

| 항목 | 제품 (45) | 중심 맞추기 c ≤ .001 (54) |
|---|---|---|
| E2 지속 평균 / 최대 \|지연\| (다운시프트) | 22–24 / 30 ms | **3 / 6–7 ms** |
| A2 | 21–25 / 30 ms | **2.4–4.9 / 5.6–12 ms** |
| E2 파워코드 | 18 / 30 ms | **7 / 17–18 ms** |
| 스플라이스/초 (다운시프트) | 4–55 | 4.5–55 (A2 −7만 18 → 28) |
| 피킹 오차 | −0.5 … +2.3 ms | 같음 |
| 레가토 / 해머온 ±5 ms 이내 | 90 % / 92 % | 79 % / 85 % (범위 −6.7 … +3.2 ms로 같음, 이른 쪽으로 이동) |
| B0 단음 spurious | −33.6 dB | −29.4 dB |
| E2 단음, D2·E2 파워코드, 나머지 화음 | | ±1.4 dB 이내 |
| A2 ±100 c 비브라토 사이클 중앙값 | 9.2 c | 20.8 c |
| CPU 블록 평균 (48 kHz, 128) | | +0–30 %, p99.9는 최대 약 2배(공유 컨테이너라 잡음 큼) |

**판정: 제품에 넣지 않는다.**
- 지속음 저역이 약 20 ms 늦는 문제는 크게 준다.
- 대신 측정 가능한 손실이 있다. B0 −4 dB, 레가토 ±5 ms 비율 감소, 극단적 비브라토, CPU 꼬리가 그렇다.
- 반면 어택은 이미 맞춰져 있어서, 지속음이 늦는 것이 들리는지는 확인되지 않았다.
- 모드 45 대 54의 청감 A/B로 판단한다. 들린다면 c = .001을 출발점으로 삼고, 이른 스플라이스 탐색의 CPU 꼬리를 줄이는 작업(탐색 범위 제한 등)이 먼저다.
