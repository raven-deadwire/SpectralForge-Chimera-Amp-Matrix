## 정확한 입력 규칙

1. ASCII만 허용하며 붙여넣기 최대 256자, 공백 제거 후 최대 64자입니다.
2. 제거 대상은 ASCII 공백, 탭, CR, LF뿐입니다. Unicode 공백·유사 문자는 거부합니다.
3. `CHT1-NAME-CHECK`의 세 부분을 `-`로 구분합니다. 접두사와 이름은 대문자로 정규화합니다. 이름은 `A-Z0-9` 2–16자입니다. **이름의 O/I/L은 바꾸지 않습니다.**
4. 확인 문자열만 대문자로 바꾸고 O→0, I/L→1로 보정합니다. 보정 후 Crockford Base32 6자여야 합니다. 이름 속 점·밑줄·하이픈을 제거하는 발급용 `check_name()` 규칙을 기존 코드에 적용하지 않습니다.
5. ASCII 바이트 `chimera-tester-allowlist-v1|` + 정규화된 전체 코드의 SHA-256을 소문자 64자리 hex로 기록합니다. 이름도 해시에 결합되며 버전이나 만료일은 결합되지 않습니다.

기존 HMAC 비밀값을 읽거나 과거 HMAC을 재계산하지 않았습니다. 기존 원문의 새 형식 호환성과 등록 후 동작을 확인한 것이며 과거 발급 자체를 암호학적으로 인증한 결과는 아닙니다. 6자리의 약 30비트 추측 한계는 #191과 동일합니다.

## 구현과 안전한 반영 절차

`Tools/tester_code.py migrate`는 Git 밖의 비공개 입력, 정확한 예상 수량, 코드·대상 중복, Python 다이제스트와 C++ 검증의 일치를 검사합니다. 원문을 프로세스 인자로 넘기거나 stdout에 출력하지 않으며, 임시 디렉터리/파일은 POSIX 0700/0600으로 만들고 검사 후 정리합니다. 네이티브 검사 오류도 원문을 출력하지 않습니다. 모든 검사가 통과한 뒤에만 새 다이제스트 전용 검토 파일을 작성하고 기존 운영 다이제스트를 보존합니다. 운영 파일이나 기존 파일을 덮어쓰지 않습니다.

남은 3개 원문을 소유자의 비공개 입력으로 확보한 뒤 **기존 5개 전체**를 `--expected-count 5`로 다시 검사합니다. 이 수량을 낮춰 부분 검사를 전체 완료로 처리하지 않습니다. 새로운 원문이 형식 검사에 실패한다면 해당 코드만 별도로 검토하고, 자동 재발급이나 추측 교정은 하지 않습니다.

완료한 5개 검토 목록과 기존 승인 목록의 차이를 확인한 뒤, 별도로 승인된 제품 소스에만 운영 다이제스트를 반영합니다. 다음 베타에서도 기존 다이제스트를 유지해야 저장된 권한이 이어집니다. 메타데이터 오류는 유효 코드로 우회할 수 없습니다. 권한의 범위는 베타 만료 해제이며 정식 제품 라이선스를 추가하지 않습니다.
