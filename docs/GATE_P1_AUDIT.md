## Control and timing contract

| Host ID | Range / default | Meaning |
| --- | --- | --- |
| `gateon` | bool / on | Enables selected gate stage. Bypass returns to unity using existing fast gain smoothing. |
| `gatethreshold` | -90..-15 dBFS / -65 | Opening threshold, measured after input gain and input-mode conversion. Closing boundary is threshold minus 6 dB. |
| `gaterelease` | 5..500 ms / 80 | One-pole **time constant**, not time to exact silence: after one release constant, 36.8% of the distance to the closed target remains. |
| `gatehold` | 0..150 ms / 20 | Loaded when detector reaches opening threshold. Countdown advances only below the closing boundary, and pauses in the hysteresis band. Release starts after the remaining count expires. |
| `gateAfterRig` | bool / off | Off: attenuate before Transpose/PRE. On: detect the same clean input, apply the aligned gain after rig/cab merge, before POST. |
| `gateRangeDb` **new** | 0..96, 0.1 step / 96 (`Full`) | 0 = no attenuation; 0.1..95.9 = positive attenuation depth in dB; 96 is the `Full` sentinel, **not a finite -96 dB floor**. |

Finite closed gain is `10^(-Range/20)`; e.g. 24 dB leaves approximately 0.063096 amplitude. `Full` targets zero with the original release curve. It does not hard-mute instantly or promise exact zero after one release interval. Full is the old behavior, sample-for-sample against a frozen baseline oracle. Range changes move the same smoothed gain target; they do not reset the detector or change threshold/hold timing. Increasing the floor uses the existing 0.5 ms attack constant, lowering it uses Release.

Attack is fixed, not a new automatable parameter. The detector takes the maximum absolute sample across channels and releases with a 20 ms time constant. Actual time from note end to attenuation includes detector decay, Hold and Release. A 0.5 ms attack constant is approximately 2.3 ms to 99% reopening, not a 0.5 ms lookahead or a reported latency.

## Routing and compatibility

The detector sees input-mode conversion → smoothed INPUT gain → clean input, before Transpose and either PRE path. Post-rig envelope delay follows the existing PRE + engine latency, using preallocated storage. Post-rig gating cannot be opened by noise created after the detector. POST compressor/preamp/EQ/modulation/delay/reverb and utility output remain downstream: delay/reverb tails survive closure; noise generated in those later stages is outside this gate. A gate does not remove hiss while its detector is open.

The prior latency-alignment startup behavior is retained: the delay's initial history is zero. This can suppress the first latency-length segment after prepare/reset, even at zero Range or bypass in the post position; this change does not claim to fix startup or live position-switch transients. Live route changes and latency-changing Transpose/oversampling remain host/listening acceptance items.

`gateRangeDb` is appended **after all** native POST parameters (index 3686); no released parameters are inserted, renamed, reordered, widened or renormalized. Parameter version hint 2 places it after existing AU hint-1 parameters. The manifest fingerprint of all 3,686 baseline parameters (index, ID, version hint, default normalized value, steps, normalized 0/0.5/1 mappings, automatable flag) is:

`1de9d010b4267088d80a6922105b047ae0c9e142e3b931c000129d6befa3523f`

The additive XML state remains schema 8. Existing `restoreCore` fills missing parameters from their declared defaults, so old projects, user presets and A/B slots without `gateRangeDb` restore Full, even if the current session was limited to 0 or 24 dB. New states persist Range as an ordinary APVTS parameter. Factory presets explicitly reset it to Full. MIDI mappings continue to save stable string IDs. Loading new state into an older binary cannot provide the new finite-floor feature; forward emulation is not claimed.

The gate meter now samples post-rig reduction **after** applying that block, removing its previous one-block reporting lag.
