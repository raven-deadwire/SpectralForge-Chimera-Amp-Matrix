## 1. 설치와 기존 세션 호환

근거: [OVERSAMPLING_AUTO.md](OVERSAMPLING_AUTO.md), [TRUE_PEAK_LIMITER_1_5.md](TRUE_PEAK_LIMITER_1_5.md).

- [ ] **설치·스캔:** 각 포맷이 호스트에서 오류 없이 스캔되고 로드됩니다. Standalone도 실행됩니다.
- [ ] **기존 세션 열기:** 공개판으로 저장한 세션을 열면 소리가 저장 당시와 같습니다. (귀로 판단. 가능하면 같은 DI를 바운스해 null 테스트)
- [ ] **기존 세션의 OVERSAMPLING:** 저장된 배율 그대로 열립니다. 예를 들어 4x로 저장했다면 메뉴에 `4x`가 표시되고, `Auto`로 바뀌지 않습니다. 96 kHz 세션에서도 마찬가지입니다.
- [ ] **기존 세션의 리미터:** 리미터 모드가 `Live`로 열리고, 호스트에 보고되는 지연이 저장 당시와 같습니다.
- [ ] **호스트 파라미터 목록:** 기존 파라미터의 이름, 순서, 오토메이션이 그대로입니다. 새 파라미터는 목록 끝에만 추가됩니다(`Output limiter mode`, `Oversampling follows sample rate` 등).

## 2. Studio true-peak 리미터

근거: [TRUE_PEAK_LIMITER_1_5.md](TRUE_PEAK_LIMITER_1_5.md). DYNAMICS → LIMITER에서 모드를 고릅니다.

- [ ] **PDC(지연 보정):** Studio를 고르면 호스트에 보고되는 지연이 1 ms + 16샘플만큼 늘어납니다(48 kHz 64샘플, 44.1 kHz 60샘플). 같은 트랙을 복제해 한쪽만 Studio로 두고 위상을 뒤집으면, 리미팅이 걸리지 않는 작은 레벨에서는 완전히 상쇄됩니다.
- [ ] **호스트별 지연 변경 반영:** 재생 중에 모드를 바꾸면 호스트가 새 지연을 받아들입니다. 호스트에 따라 재생을 멈췄다 다시 시작해야 반영될 수 있으니, 어떤 경우였는지 기록합니다.
- [ ] **상한 유지:** 상한을 −1 dBTP로 두고 큰 신호(OUTPUT +12 dB)를 넣습니다.
  - 기준: 플러그인 OUTPUT의 `TP` 표시가 −1.0 dBTP를 넘지 않습니다.
  - 가능하면 호스트나 외부의 true-peak 미터 값도 함께 적습니다. 외부 미터는 보간 필터가 달라 0.0x dB 정도 차이 날 수 있습니다.
- [ ] **Live와의 차이:** 같은 신호에서 Live는 샘플 피크만 막으므로 외부 true-peak 미터가 상한보다 높게 읽을 수 있습니다. Studio는 그렇지 않습니다.
- [ ] **모드 전환 클릭:** 사인이나 지속음을 재생하면서 Live ↔ Studio를 여러 번 바꿉니다.
  - 기준: 약 20 ms 동안 소리가 잠깐 줄어드는 것 외에 클릭이나 팝이 없습니다. Studio로 갈 때는 약 1.3 ms 더 무음입니다.
- [ ] **오프라인 바운스:** 실시간 재생과 오프라인 바운스의 결과가 같습니다. 상한도 똑같이 지켜집니다.
- [ ] **호스트 바이패스:** Studio 상태에서 호스트 바이패스를 켜고 꺼도 시간 어긋남이나 클릭이 없습니다.

## 3. OVERSAMPLING Auto

근거: [OVERSAMPLING_AUTO.md](OVERSAMPLING_AUTO.md).

- [ ] **새 인스턴스:** 메뉴가 `Auto (4x)`(44.1/48 kHz), `Auto (2x)`(88.2/96 kHz), `Auto (1x)`(176.4/192 kHz)로 표시됩니다.
- [ ] **세션 샘플레이트 변경:** 48 → 96 kHz로 바꾸면 표시가 `Auto (4x)`에서 `Auto (2x)`로 바뀌고, 소리가 끊기거나 튀지 않습니다.
- [ ] **호스트 오토메이션·제네릭 UI (중요):** 호스트의 제네릭 파라미터 화면이나 오토메이션으로 `Oversampling`을 바꿉니다(예: 8x).
  - 기준 1: 호스트 화면의 `Oversampling follows sample rate`가 **꺼짐으로 바뀌어 보입니다**.
  - 기준 2: 그 상태에서 호스트 화면으로 Auto를 다시 켤 수 있습니다.
  - 기준 3: 플러그인 메뉴도 `8x`를 표시합니다.
  - VST3, AU, AAX 각각 확인합니다. 이 항목은 CI에서 래퍼 동작을 흉내 낸 테스트만 했습니다.
- [ ] **저장·복원:** Auto, 수동 배율 각각 저장 후 다시 열면 그대로입니다.
- [ ] **A/B:** A는 Auto, B는 수동 2x로 두고 전환하면 각자의 설정이 유지됩니다.
- [ ] **팩토리 프리셋:** 프리셋을 불러오면 OVERSAMPLING이 Auto로 초기화됩니다(이전에는 4x). 48 kHz에서는 이전과 같은 소리입니다.
- [ ] **지연:** Auto나 어떤 배율로 바꿔도 호스트에 보고되는 지연은 변하지 않습니다.

## 4. AUTO SET 위치

- [ ] **전체 에디터:** 로고 옆 금색 **AUTO SET**이 모든 페이지에서 보입니다.
  - 누르면 Auto Set이 시작되고 DYNAMICS 화면(진행 상황, 옵션, UNDO)이 열립니다.
  - 듣는 동안 붉은 **CANCEL**로 바뀌고, 누르면 취소됩니다.
- [ ] **Easy 화면:** "3 GET READY"의 금색 AUTO SET이 같은 동작을 합니다.
- [ ] **Standalone 입력 음소거 안내:** 입력이 음소거되어 상단 안내 배너가 보이는 동안 상단 AUTO SET은 숨겨져 있습니다. INPUT ON 후 다시 나타납니다.
- [ ] **화면 배율:** 75%, 100%, 125%, 150%와 Fit screen에서 버튼이 잘리거나 다른 컨트롤과 겹치지 않습니다.
- [ ] **실제 연주 Auto Set:** 기타와 베이스로 한 번씩 끝까지 실행합니다(약 1분).
  - phase 11(딜레이·리버브)과 phase 12(PRESENCE·RESONANCE) 행이 결과에 나옵니다.
  - UNDO AUTO로 모두 되돌아갑니다. 결과가 납득되는지는 귀로 판단합니다.

## 5. SYNTH 버스와 사이드체인 (멀티 출력 호스트)

근거: [SIDECHAIN_SYNTH_BUS.md](SIDECHAIN_SYNTH_BUS.md).

- [ ] **버스 구성:** 호스트에서 Sidechain 입력과 Synth 출력 버스를 켜고 끌 수 있습니다. 끄면 메인 출력만 남습니다.
- [ ] **SYNTH 버스 정렬:** `synthOutput`을 Synth bus로 두고 메인과 SYNTH 버스를 함께 녹음하면 시간이 맞습니다. Studio 리미터를 켠 상태에서도 확인합니다.
- [ ] **SYNTH 버스에는 리미터 없음:** 의도된 동작입니다. 필요하면 DAW 트랙에서 리미팅합니다.
- [ ] **외부 키:** 사이드체인으로 킥을 넣고 컴프레서·게이트·멀티밴드의 EXT KEY를 켜면 키 신호에 반응합니다.

## 6. 실제 녹음으로 트래킹 검증 (1.10)

근거: [TRACKING_1_10.md](TRACKING_1_10.md). 이 브랜치에서 아직 남아 있는 1.10 항목입니다.

- [ ] **녹음:** 48 kHz, 24-bit, 모노 DI. 이펙트 없이 피크 −12 ~ −6 dBFS로 녹음하고, 프레이즈 사이에 0.5초 이상 무음을 둡니다.
- [ ] **소재:** 각 개방현 지속음, 악기의 최저음(7현 B, 드롭 튜닝, 베이스 E·B), G·B현 온음 벤드와 비브라토, 해머링·풀링, 팜뮤트 16분음표 120 BPM, 얼터네이트 16분음표 160 BPM, 12프렛 하모닉스, 15프렛 위 고음, 파워코드, 무음 몇 초(험·히스).
- [ ] **실행:** `ChimeraTrackingCheck take.wav`(레이블 파일이 있으면 `--labels take.csv`). 결과 표와 실패 노트를 기록합니다.
- [ ] **기준:** 문서의 목표를 씁니다.
  - 음 잡힘(lock) 60 ms 이내, 55 Hz 아래는 80 ms 이내.
  - 피치 오차 중앙값 10센트 이내.
  - 지연 25 ms 이내.
