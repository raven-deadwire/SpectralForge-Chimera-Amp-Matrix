## 출하를 막는 항목

1. **정확한 통합 소스의 Windows/macOS/Linux 전체 빌드·검사·패키지**.
   #66의 CAB/EQ 실패 중 파라미터 개수 3개 검사는 #68에서 이미 19+40개
   추가분을 반영했다. 실제 순서/기본값/고유 ID 검사는 계속 유지한다.
2. **튜너 지연**. #67의 48k/256/E2 pitch-step 305.65 ms는 290 ms 기준
   실패다. macOS CI에서도 acquisition 290 ms 초과가 있었다. 이번 통합에서
   기준을 올리거나 재시도 성공만 남기지 않는다.
3. **UI**. #67 macOS의 별도 창 bounds 실패는 내장 작업공간 채택 후 새
   bounds 검사로 재확인한다. 간헐적인 acquisition 실패도 미해결 증거로 남긴다.
4. **실시간 오디오**. 570%/966.5%는 전체 PC CPU가 아니라 콜백 시간/버퍼
   기한이다. 튜너 ON/OFF, UI open/closed의 동일 콜백 wall/thread 기록과
   전체 dynamics 부하가 필요하다. 관측 도구 종료 코드 0은 성능 PASS가 아니다.
5. **설치·상태·사용자 자산**. 설치/업데이트/복구/제거, beta.2 상태→새 후보,
   개인 IR·프리셋·A/B·MIDI, macOS 반복 복원, 실제 설치 VST3/AU/앱 검사가
   새 SHA에 연결돼야 한다. 예전 #62의 PASS를 통합본에 상속하지 않는다.
6. **출하 정책**. 베타 만료 절대 시각 승인 없음. qualification-only 패키지는
   게시 불가. `RELEASE_REVIEW_PENDING` 및 기존 미실행 acceptance는 유지한다.
   소스·버전별 승인, 실제 패키지 SHA-256, 업데이트 경로 검증이 필요하다.

## 추가로 재현한 튜너 회귀

`e2373d7f` 통합본에서 110 Hz 입력의 좌우 크기를 매 블록 0.017 dB씩
교대하면 매번 입력 채널이 변경돼 분석 창을 채우지 못하고 640 ms 후에도
0 Hz를 반환했다. 채널 선택에 3 dB 차이를 요구하도록 수정하여 작은 좌우
변동에는 현재 채널을 유지한다. 실제 우세 채널 교체에서는 기존 측정값을
즉시 무효화하는 #67의 계약을 보존한다. 회귀 검사는 작은 변동의 연속
검출과 실제 110→220 Hz 채널 전환 후 재획득을 모두 확인한다.

첫 로컬 native worker 비교에서는 32경로 중 5경로가 실패했다. 이 실행은
공유 환경의 다른 컴파일과 겹쳤으며 지연 원인을 확정하는 실험이 아니다.
원시 결과를 보존하고, 이를 깨끗한 실시간 환경의 성능 수치나 PASS로 사용하지
않는다. 후속 실행도 실패 기록을 대체하지 않는다.

채널 수정 후 회귀(연속 검출·실제 채널 교체)는 PASS. 전체 native 검사는
32경로 중 10경로가 실패하여 **FAIL 유지**다. 108개 커널 비교는 완료됐지만
이를 전체 성능 통과로 합산하지 않는다. 두 실행의 원시 CSV, 로그와 소스/바이너리
식별을 `docs/evidence/132-reconciliation-20261014/`에 남긴다. 전체 제품의
Windows/macOS/Linux 빌드·설치·복원·콜백 승인과 실제 악기/호스트 검증은 아직
완료되지 않았다. 공개 패키지와 피드 변경은 진행하지 않는다.
