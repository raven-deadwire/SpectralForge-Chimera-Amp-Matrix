# Transpose 블록 분할 문제 수정 후보 corr40-split-v3 — 2026-10-24 KST

**결론: `corr40-split-v3`는 호스트 블록 분할과 관계없이 출력이 비트 단위로 같다. 블록 분할 의존성은 해결했다.** 그러나 사전 등록한 새 시드 검증에서는 **T3가 비회귀 상한을 넘어 통과 규칙을 만족하지 못했다.** 초과 위치는 B0 긴 음 업시프트, 15.66ms(상한 15.5)다.

이 초과는 v2에서도 같은 값으로 나온다. 이번 변경 때문이 아니라 v2에 원래 있던 여유 부족(이전 검증에서 0.37ms)이 새 시드에서 드러난 것이다.

엔진 코드는 연구용(`Tools/TransposeNext`)만 바꿨다. 제품 `Source/`는 바꾸지 않았다. 측정은 모두 합성 입력이다.

## 문제와 수정

**문제.** T6 호스트 점검(`TRANSPOSE_T6_LISTENING_DAW.md` §3)에서 v2 출력이 DAW 블록 분할에 따라 달라졌다.

- **원인 장치:** rt 단계에서 넣은 '두 경로의 접합 검색이 한 콜백에서 겹치지 않게' 하는 보류다.
- **원래 판정:** '이번 처리 구간(= 호스트 블록)에서 고역 경로가 접합했으면, 저역 경로의 다운시프트 접합을 미룬다.'
- 구간이 곧 호스트 블록이라 결과가 블록 경계에 따라 달라졌다.

**수정 (`setHoldSource`).** 저역 접합이 필요해진 샘플 i에서, 고역 경로가 **i 이전 128샘플 안에** 접합했으면 미룬다.

- i보다 뒤의 접합은 보지 않으므로 블록을 어떻게 나눠도 같은 결정이 나온다.
- 미루는 최대 길이(지연 32샘플 분량)와 다운시프트에만 적용하는 규칙은 v2와 같다.
- 고역 경로는 접합 시점을 최근 8개까지 기록한다(실시간 할당 없음).

**옵션.** 이 동작은 `TransientSplitPitch::prepare`의 새 인자로 켤 때만 쓰인다. 기존 엔진은 바뀌지 않는다.

## 결과

### 1. 기존 엔진 무변경

v2·rt·lpc·제품 엔진의 출력과 onset 위치를 변경 전 빌드와 비교했다. 조합은 3 표본률 × 전체 입력 × 4 반음으로, 2,448개 모두 비트 동일했다. 네이티브 회귀 테스트 4종도 통과했다.

### 2. 블록 불변성

고정 128 블록 출력과 다음 13가지 블록 패턴을 비교했다.

- 고정: 1/37/64/100/256/512/1024/2048/4096
- 무작위 1–512: 시드 3개
- 무작위 1–4096

| 입력 | v2 | v3 |
|---|---|---|
| 기존 입력 180조합 (2,340패턴) | 16조합·70패턴 차이, 최대 1.7e-3 | **0** |
| 새 시드 입력 360조합 (4,680패턴, 사전 등록 판정) | — | **0 → PASS** |
| VST3 호스트 점검 72회: 가변 블록 / 큰 블록 | 68/72 / 차이 24/216 | **72/72 / 차이 0/216** |

VST3 호스트 점검의 나머지 항목(고정 블록, 지연 보고 0, 재준비, 상태 복원, 자동화)도 v3에서 72/72였다.

### 3. 지연 목표 (사전 등록한 새 시드)

**조건:**

- 새 시드: holdout 14142/17320/22360, 긴 음 1414
- 렌더 수: 엔진마다 1,404회, 그중 새 시드 입력 360회
- 사전 등록은 렌더 전에 커밋 `161343a`로 push했다.
- 렌더러는 커밋 `549e475`에서 빌드했다.

| 기준 | v3 | v2 (참고) |
|---|---|---|
| T1 어택 | PASS 5.67ms | PASS 5.67ms |
| T2 다운시프트 저역 (짧은 음 / 긴 음) | PASS 6.34 / 9.07ms | PASS 6.34 / 9.07ms |
| T3 업시프트 저역 (짧은 음 / B0 / A0 / A1, 상한 12.0 / 15.5 / 19.0 / 11.0) | **초과**: 10.54 / **15.66** / 18.78 / 9.73ms | **초과**: 같은 값 |
| T4 오검출 / 누락 / 워블 | PASS 0 / 0 / 0.59 cents | PASS 0 / 0 / 0.59 cents |

- **T3 초과 위치:** 새 시드 긴 음(1414) B0 +2반음이다. 44.1kHz 15.66ms, 48kHz 15.65ms였다.
- **A0:** 18.78ms로 상한까지 0.22ms가 남았다.
- **v2와의 비교:** 출력이 다른 렌더는 720개 중 다운시프트 5개뿐이다. T1–T4 수치는 모두 같다.
- **기존 시드:** 결과도 v2와 같았다. T1 5.58, T2 6.38/9.34, T3 상한 이내, T4 0/0(`known-seed-corr40-split-v3.log`).

### 4. 실시간 (T5, 보고)

**두 경로가 같은 콜백에서 모두 접합 검색을 한 횟수.** 조합은 3 표본률 × 3 악기 × 8 입력 × 4 반음이다.

| 블록 | v2 전체 (그중 다운시프트) | v3 전체 (그중 다운시프트) |
|---|---|---|
| 64 | 632 (0) | 632 (0) |
| 128 | 755 (0) | 756 (1) |
| 256 | 900 (0) | 990 (90) |

- 업시프트는 원래 보류 대상이 아니어서 v2에서도 수백 회 있었다.
- v3에서는 다운시프트에서도 일부 생긴다. 블록과 무관하게 하려면 '같은 콜백 안에서 더 뒤에 올 고역 접합'을 볼 수 없기 때문이다.

**최악 콜백 thread CPU.** 48kHz, 5회 중앙값이며, 공유 VM이라 잡음이 크다.

| 블록 | v2 | v3 |
|---|---|---|
| 64 | 311µs | 224µs |
| 128 | 240µs | 331µs |
| 256 | 329µs | 212µs |

블록마다 어느 쪽이 큰지가 바뀌어 잡음 범위로 본다. 어느 쪽이든 콜백 한계(1,333/2,667/5,333µs)의 25% 이하다. 전용 하드웨어 측정은 여전히 필요하다.

## 판단

- **블록 분할 의존성:** v3로 해결했다. DAW 바운스가 버퍼 설정과 관계없이 재현된다. T6 DAW 수용에 필요한 성질이다.
- **사전 등록 판정:** T3 상한 초과로 **v3는 FAIL**이다. 규칙에 따라 결과를 본 뒤 상한이나 입력을 바꾸지 않는다.
- **T3 초과의 원인:** v3 변경이 아니다. v2에서도 같은 값이 나온다. 시간영역 접합의 업시프트 하한(B0/A0 긴 음 15–21ms) 근처에서 상한(첫 측정값 + 1ms)이 새 음 구성에 대해 너무 빠듯했다.
- **다음 선택지:**
  1. **상한 재정의:** 상한은 '악화를 잡는 선'이다. 근거(여러 시드에서 잰 분포)를 먼저 문서화한 뒤 다시 정한다. 정한 뒤에는 다시 새 시드로 검증한다. 운영 규칙상 판정을 통과시키려고 바꾸는 것은 금지다.
  2. **업시프트 저역 개선:** 원래 과제로 돌아간다(구조적 하한이 있음).
  3. **v3 채택 범위 한정:** 블록 불변성이 필요한 DAW 시험용으로 v3를 쓰고, T3는 v2와 같은 한계로 보고한다.
