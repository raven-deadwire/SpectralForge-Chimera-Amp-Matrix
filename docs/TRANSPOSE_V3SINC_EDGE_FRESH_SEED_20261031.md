# v3-sinc-edge 새 시드 검증 — 2026-10-31 KST

**대상.** 연구 후보 `corr40-split-v3-sinc-edge`다. v3-sinc에 고역 경로의 접합 탐색 '범위 끝 보정'을 더한 엔진이다(`setSpliceEdgeRefine`, `TRANSPOSE_SPLICE_EDGE_107HZ_20261030.md`). 기준 엔진은 `corr40-split-v3-sinc`다.

**결론: 사전 등록한 다섯 기준(E1–E5)을 모두 통과했다.**

- **기본음 107Hz 계열 잔여:** fc·2fc·3fc 부근 스윕에서 v3-sinc는 −50dB를 넘는 경우가 87건이었다(최악 −24.4dB). 수정판은 0건이다(최악 −54.1dB).
- **지연·검출:** v3-sinc와 같다.
  - 검출 수: 792/792 렌더에서 같다.
  - T1–T3 요약값: 차이 0이다.
  - 저역 지연: 차이가 최대 0.032ms다.
- **일반 시험음 세트:** 중앙값이 v3-sinc와 같다.
- **블록 분할:** 5,616개 비교 모두 차이 0이다.

제품 `Source/`는 바꾸지 않았다. 새 선택지는 기본값이 꺼져 있다. 측정은 합성 입력만 썼다.

## 엔진 선택지

- `CorrelationPitch::setSpliceEdgeRefine(bool)`를 추가했다. 기본값은 꺼짐이다.
  - **규칙 1:** 탐색 범위 끝에서 찾은 최솟값의 바로 바깥 비용이 더 낮으면, 그 끝을 거친 격자 한 칸만큼 줄여 다시 찾는다(최대 2회 더).
  - **규칙 2:** 범위 끝에서도 바깥 이웃 비용으로 포물선 보정을 한다.
- `TransientSplitPitch::setSpliceEdgeRefine(bool)`는 고역(transient) 경로에만 적용한다.
- `TransposeProbe`에 엔진 이름 `corr40-split-v3-sinc-edge`를 추가했다. `SpliceTrace`와 `BlockInvariance`는 `v3-sinc-edge`를 받는다.

**확인한 것.**

- 선택지를 끄면 v2·v3·v4·v3-sinc 출력이 `main`(c4d5431) 빌드와 비트 동일하다(72 렌더).
- `CorrelationTests`는 324 그룹 PASS다.
- 새 엔진은 10/30 실험 패치와 같은 출력을 낸다. 612점 fc 스윕 결과가 모두 같았다.

## CPU (보고만, 공유 VM)

48kHz, 콜백당 스레드 CPU를 쟀다. 세 번 번갈아 잰 값의 중앙값이다.

| 입력 | 블록 | v3-sinc 평균 / p99 / 최대 | v3-sinc-edge 평균 / p99 / 최대 |
|---|---:|---|---|
| B0 긴 음 | 64 | 12.7 / 56.6 / 129µs | 13.1 / 46.1 / 111µs |
| B0 긴 음 | 128 | 29.4 / 84.1 / 196µs | 26.0 / 82.0 / 138µs |
| A0 긴 음 | 64 | 13.2 / 53.7 / 128µs | 13.7 / 53.7 / 97µs |
| A0 긴 음 | 128 | 26.3 / 85.0 / 152µs | 27.5 / 88.5 / 141µs |
| fc 시험음 (106.8Hz) | 64 | 13.7 / 70.5 / 177µs | 14.4 / 70.5 / 222µs |
| fc 시험음 (106.8Hz) | 128 | 26.5 / 99.1 / 184µs | 26.8 / 91.0 / 195µs |

- 평균과 p99는 VM 흔들림 범위 안에서 같다.
- fc 시험음에서는 범위 끝 재탐색이 실제로 일어난다. 이때 64샘플 블록 최대가 177 → 222µs였다. 다만 공유 VM의 최대값은 흔들림이 크다.
- T5 판정은 전용 하드웨어에서 해야 한다.

## 의미

1. **v3-sinc-edge의 지위.** 합성 입력 기준으로 107Hz 계열 잔여를 없앴다. 지연·검출·블록 분할은 v3-sinc와 같다. 그래서 v3-sinc를 대체할 연구 후보가 된다.
2. **남은 일.**
   - T6 청취
   - 전용 하드웨어 CPU(T5)
   - 실제 DI 검증
   - 업시프트 마커 꼬리 다시 읽기(별도 과제)
3. **저역 경로.** 수정을 적용하지 않았다. 저역 경로는 정확한 정수 주기를 점프하고 있었고, 저역에도 적용하면 저역 지연이 바뀌었기 때문이다(10/30 분석).
