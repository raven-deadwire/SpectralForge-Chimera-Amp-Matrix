# 호스트 검증 체크리스트 — EQ 표시 범위와 커서 수치 표시 (2026-11-05 KST)

PR #261(Issue #53)에서 추가한 그래픽 EQ의 **표시 범위(±6 / ±12 / ±24 dB)**와 **커서 수치 표시** 가운데, CI의 자동 테스트로는 확인할 수 없는 것을 실제 DAW에서 확인하기 위한 목록입니다. 절차 검토일은 2026-11-06 KST이며, 문서·구현 기준은 PR #268 HEAD `a60fb5f30d6a27fac4b36c962576352ca13e8332`입니다. 이 문서 수정 자체는 실제 DAW 시험 결과가 아닙니다.

- **자동 테스트가 확인한 것:** `ChimeraGraphicalEQUITests`의 `displayRangeAndReadout`과 `liveAnalyzer`. 범위별 노드 위치, 지원하지 않는 값의 기본 범위(±24) 복귀, 범위 전환 후 저장 상태·모든 호스트 파라미터·플러그인 EQ Undo/Redo·A/B 슬롯 불변, 화면 밖 노드의 가장자리 표시와 실제 값 기준 드래그, A/B·공장 프리셋 뒤 범위 유지, 합성 오디오를 실제 프로세서에 입력한 IN/OUT/LIVE/Freeze 조합별 수치 문자열입니다. 실제 DAW의 Undo 스택이나 메뉴를 조작한 시험은 아닙니다. 아래의 수동 반복은 호스트 통합 확인용입니다.
- **CI가 확인하지 못한 것:** 오른쪽 클릭 메뉴 자체(비동기 팝업), 메뉴가 열린 채 에디터를 닫는 경우, 실제 DAW 창에서의 표시, 호스트 자신의 Undo·프로젝트 저장·오토메이션과의 관계.
- **판정:** 항목마다 **PASS / FAIL / 보류**를 적고, FAIL이면 재현 방법을 함께 적습니다. 환경 미확보·호스트 미지원·목표 상황을 만들지 못한 시험은 이유를 붙여 **보류**로 남깁니다. 포맷상 해당하지 않는 항목은 `해당 없음`으로 표시하고 PASS 집계에서 제외합니다.

## 0. 준비

- [ ] **빌드 기록:** 테스트한 전체 커밋 SHA(#261 포함 여부 확인), 설치 파일/플러그인 버전과 로드 경로, OS와 버전, 호스트와 버전, 포맷(VST3 / AU / AAX / Standalone), 실제 처리 샘플레이트, 버퍼 크기, 장치·드라이버, OS 배율과 플러그인 UI 배율을 각각 기록합니다. 최신 빌드는 위 기준 SHA와 별도로 적습니다.
- [ ] **시험 신호:** 44.1 또는 48 kHz의 별도 시험 프로젝트에서 1 kHz 사인, 약 −20 dBFS를 트랙에 재생합니다. 다른 처리와 변조를 우회해 안정적인 입력을 만들고, 클리핑·게이트 닫힘·무음을 피합니다. 파괴적인 메뉴 시험은 이 복제 프로젝트에서 합니다.
- [ ] **EQ 설정:** 새 인스턴스에서 `+ BAND`로 Band 1을 만들고 **Bell**, 1 kHz, +6 dB, Q 약 0.707로 설정합니다. `BAND ON`은 켜고 `BYPASS EQ`는 끕니다. 다른 밴드와 DYNAMIC은 끕니다. 분석기는 LIVE·IN·OUT을 켜고 Freeze·PEAK는 끕니다. 수치가 안정되고 FREEZE 버튼이 활성화될 때까지 기다립니다.
- [ ] **양쪽 EQ:** 1~4번은 Tone EQ와 Final EQ에서 각각 기록합니다. 대상 EQ만 위 조건으로 설정하고 다른 EQ는 우회합니다. 시험 중 편집한 뒤 다음 항목에 들어가기 전에 이 기준 상태를 복원합니다.

## 1. 오른쪽 클릭 표시 범위 메뉴

- [ ] **메뉴 열기:** 그래프의 빈 곳을 오른쪽 클릭하면 "EQ display range" 제목과 `+/-6 dB`, `+/-12 dB`, `+/-24 dB` 항목이 뜹니다.
- [ ] **현재 범위 표시:** 현재 범위에 체크 표시가 있습니다. 새로 생성된 에디터는 `+/-24 dB`입니다. 호스트가 창을 숨겼다가 같은 에디터를 다시 표시하는 경우에는 기존 범위를 유지할 수 있습니다.
- [ ] **전환:** 각 항목을 고르면 바로 다시 그려집니다.
  - 기준: 가로 격자와 숫자 간격은 아래와 같습니다. 0 dB 선은 밝게 그려집니다.

    | 범위 | 격자 간격 | 숫자 |
    |---|---|---|
    | ±24 dB | 6 dB | −24, −12, 0, +12, +24 |
    | ±12 dB | 3 dB | −12, −6, 0, +6, +12 |
    | ±6 dB | 1 dB | −6, −3, 0, +3, +6 |
- [ ] **노드 위 오른쪽 클릭:** 밴드 노드 위에서는 범위 메뉴가 아니라 `Delete Band N` 메뉴가 뜹니다. 좁은 범위에서 가장자리에 붙은 노드도 마찬가지입니다.
- [ ] **macOS 입력 [macOS 필요]:** Ctrl+클릭, 보조 클릭으로 설정된 트랙패드 두 손가락 클릭에서도 같은 메뉴가 뜹니다. Windows에서는 이 항목을 대신 판정하지 않습니다.
- [ ] **취소:** 메뉴를 연 채 Esc를 누르거나 바깥을 클릭하면 아무것도 바뀌지 않습니다.
- [ ] **메뉴가 열린 채 에디터 닫기 (중요):** 메뉴를 연 상태에서 아래 방법으로 에디터를 닫습니다. 방법마다 따로 확인합니다.
  - 범위 메뉴와 `Delete Band N` 메뉴를 각각 열고, 호스트의 플러그인 창 닫기 버튼·해당 창 닫기 단축키·트랙 삭제·플러그인 제거를 시도합니다. 시험 프로젝트에서 가능한 경로마다 3회 반복하고, 어떤 대상이 닫혔는지 기록합니다.
  - 팝업이 첫 클릭/키 입력을 취소 동작으로 소비하는지 화면 녹화로 구분합니다. **메뉴가 먼저 닫힌 뒤 에디터가 닫힌 경우는 일반 닫기/취소만 확인한 것**입니다. 실제로 팝업이 열린 상태에서 에디터가 제거되는 경로가 없으면 해당 수명 시험은 `보류 — 호스트가 팝업을 먼저 해제`로 남깁니다.
  - 기준: 크래시·멈춤·유령 메뉴가 없고, 대기 중이던 메뉴 콜백이 다른 인스턴스/밴드를 바꾸지 않습니다. 기존 인스턴스의 창만 닫았다면 EQ 값은 유지되어야 합니다. 같은 에디터를 숨겼다가 표시하면 범위를 유지할 수 있고, 에디터가 재생성되면 ±24입니다. 제거/트랙 삭제 후에는 새 인스턴스를 삽입해 정상 동작과 ±24 초기값을 확인합니다. 삭제한 인스턴스의 값을 새 인스턴스에서 요구하지 않습니다.
- [ ] **메뉴가 열린 채 다른 조작:** Tone EQ ↔ Final EQ 전환과 호스트가 허용하는 창 크기/UI 배율 변경을 시도합니다.
  - 메뉴가 취소되면 범위·EQ 값이 그대로여야 합니다. 메뉴가 유지되어 항목을 선택할 수 있으면 범위는 메뉴를 열었던 패널에만 적용되어야 합니다. 현재 표시 패널에 잘못 적용하거나 크래시가 나면 FAIL입니다. 메뉴 유지가 불가능한 경로는 보류 사유를 적습니다.
- [ ] **메뉴 위치:** 화면 가장자리, 다중 모니터, 배율이 다른 모니터에서 메뉴가 잘리지 않고 플러그인 창이 있는 모니터에 뜹니다.

## 2. 커서 수치 표시

- [ ] **표시와 사라짐:** 그래프 위에 마우스를 올리면 그래프 오른쪽 위 상자에 `주파수   ±dB`가 뜹니다. 그래프 밖으로 나가면 사라집니다. 이 dB는 **커서의 세로 좌표**이며 EQ 응답 곡선의 게인이나 dBFS가 아닙니다. 같은 주파수에서 위아래로 움직이면 이 dB만 바뀌고, 고정된 스펙트럼의 dBFS는 같아야 합니다.
- [ ] **형식:** 1 kHz 이상은 `1.00 kHz`처럼 소수 둘째 자리, 100 Hz~1 kHz는 정수 Hz, 100 Hz 미만은 소수 첫째 자리 Hz입니다. dB는 `+6.0 dB`처럼 부호와 소수 첫째 자리입니다.
- [ ] **드래그 중 갱신:** 노드를 드래그하는 동안에도 커서 위치 값이 갱신됩니다. 가장자리에 고정된 +18 dB 노드를 ±6 범위에서 가리킬 때 커서 dB와 실제 밴드 게인이 다른 것은 정상입니다. 실제 값은 밴드 GAIN 필드로 판정합니다.
- [ ] **가림·잘림:** 오른쪽 위 상자가 그래프 안에 있고 문자열이 잘리지 않는지, 툴바를 덮거나 노드 선택을 방해하지 않는지 확인합니다. 상자는 그래프 위에 그려지므로 배경 스펙트럼/곡선과 겹치는 것 자체를 FAIL로 보지 않습니다. 지원되는 창 크기/UI 배율에서 확인하고 읽기 어려운 겹침은 캡처합니다. 컴팩트 작업 공간은 해당 빌드에서 실제 진입 가능한 경우에만 확인하며 진입 경로가 없으면 해당 없음으로 기록합니다.
- [ ] **화면 배율:** 100% / 150% / 200%(Windows), Retina와 일반 모니터(macOS)에서 글자가 흐리거나 상자 밖으로 넘치지 않습니다.
- [ ] **상태별 레벨 표시:** 완전한 분석 데이터가 있는 상태에서 커서를 1 kHz의 같은 위치에 두고 아래 조합을 확인합니다. 레벨 없음은 `IN/OUT … dBFS` 부분만 없다는 뜻입니다. 주파수·커서 dB는 남습니다. IN/OUT은 해당 EQ 직전/직후이며 플러그인 전체 입출력이 아닙니다.

  | LIVE | IN | OUT | Freeze | 기준 |
  |---|---|---|---|---|
  | 켬 | 켬 | 켬 | 끔 | `OUT … dBFS` |
  | 켬 | 켬 | 끔 | 끔 | `IN … dBFS`, 동일 주파수의 OUT보다 약 6 dB 낮음(자동 시험과 같은 확인 범위: 차이 3~9 dB 사이) |
  | 켬 | 끔 | 켬 | 끔 | `OUT … dBFS` |
  | 켬 | 끔 | 끔 | 끔 | **레벨 없음** (주파수와 dB만) |
  | 끔 | 아무거나 | 아무거나 | 끔 | 레벨 없음, 그래프에 "Analyzer off" |
  | 켬·조작 잠김 | 켬 | 켬 | 켬 | `OUT … dBFS`, 재생을 멈춰도 같은 주파수의 값 유지 |
  | 켬·조작 잠김 | 켬 | 끔 | 켬 | `IN … dBFS`, 고정된 값 |
  | 켬·조작 잠김 | 끔 | 켬 | 켬 | `OUT … dBFS`, 고정된 값 |
  | 켬·조작 잠김 | 끔 | 끔 | 켬 | **레벨 없음** |

  Freeze 행은 LIVE를 다시 켜서 새 데이터가 들어온 뒤 FREEZE를 눌러 진입합니다. `FROZEN` 표시와 LIVE·RESOLUTION·SMOOTHING 잠김을 확인하고, IN·OUT만 조합합니다. Freeze 중 LIVE를 끄는 조작을 요구하지 않습니다. 아직 완전한 프레임을 얻지 못한 초기 상태에서는 FREEZE가 비활성인 것이 정상입니다.

- [ ] **Freeze 유지·해제:** Freeze 중 Tone EQ ↔ Final EQ를 오갔다 돌아와도 같은 주파수의 스펙트럼 dBFS가 그대로입니다. 해제 후에는 이전 스냅샷을 새 데이터처럼 표시하지 않아야 합니다. 재생 중에는 새 분석창이 완성되면 갱신되고, 콜백이 멈춘 호스트에서는 재생을 재개할 때까지 기다릴 수 있습니다.
- [ ] **재생 정지:** Freeze를 끈 상태에서 확인합니다. 호스트가 무음 콜백을 계속 공급하면 floor 수준의 수치가 남을 수 있습니다. 콜백을 중단하면 live 데이터가 감쇠·소멸한 뒤 레벨 부분이 사라지고 `Waiting for fresh audio`가 표시됩니다. 정지 즉시 레벨이 사라져야 한다고 판정하지 않습니다. LIVE를 끄면 레벨 없음과 `Analyzer off`를 확인합니다.

### 2-1. 나이퀴스트 경계 — 32 kHz 조건부 시험

그래프의 주파수 범위는 20 Hz~20 kHz입니다. `readoutAt`은 **커서 주파수 < 분석 프레임 샘플레이트 / 2**일 때만 레벨을 붙입니다. 정확히 나이퀴스트인 지점도 레벨이 없습니다. Freeze에서는 현재 장치 설정이 아니라 **캡처한 프레임의 샘플레이트**가 기준입니다.

- [ ] **지원·실제 레이트 확인:** 별도 프로젝트에서 DAW와 선택 장치/드라이버가 32 kHz를 실제 처리 레이트로 허용하는지 확인합니다. 설정 표시와 플러그인 RESOLUTION 툴팁의 `at 32.0 kHz`를 함께 기록합니다. 32 kHz 파일을 48 kHz 세션에 넣거나 내보내기 레이트만 32 kHz로 바꾸는 것은 이 시험이 아닙니다.
- [ ] **유효 데이터 대조:** 이전 Freeze를 해제하고 32 kHz에서 새 분석 데이터를 받습니다. LIVE·IN·OUT 켬으로 1 kHz에서 `OUT … dBFS`가 보이는지 먼저 확인합니다. 양쪽 토글 숨김/LIVE 끔/무데이터 때문에 레벨이 없는 상태로 시험하지 않습니다.
- [ ] **경계 양쪽:** 그래프 안쪽의 약 15 kHz에서는 레벨 문자열이 있고, 약 17~19 kHz에서는 주파수·커서 dB만 남는지 확인합니다. 실제 고역 에너지가 없어도 floor 수치는 레벨 표시로 인정합니다. 16.00 kHz의 반올림 표시나 그래프 바깥으로 나간 커서로 경계를 판정하지 않습니다. OUT을 끄고 IN만 켠 경우에도 반복합니다.
- [ ] **Freeze 대조:** 32 kHz의 완전한 프레임을 Freeze하고 같은 두 위치를 확인합니다. 전체 작업 공간의 `Snapshot / 32.0 kHz / …` 표시도 기록합니다. 다른 레이트에서 캡처한 이전 Freeze는 쓰지 않습니다.
- [ ] **44.1/48 kHz 비교:** 새 데이터를 받은 상태에서 약 19 kHz(그래프 안쪽)는 각각 나이퀴스트 22.05/24 kHz 미만이므로 레벨 문자열이 남아야 합니다. 이것은 일반 표시 확인이며 나이퀴스트 차단 시험의 대체가 아닙니다.

**32 kHz 미지원 시 결정:** 이 경계 시험은 `보류 — 실제 32 kHz 처리 미지원`으로 남기고, 호스트·장치·드라이버와 거부/자동 변환된 레이트를 기록합니다. 나머지 44.1/48 kHz 시험은 계속합니다. 지원되는 다른 드라이버/호스트 또는 Standalone에서 실제 32 kHz가 확인되면 그 환경의 보조 결과로 따로 기록하되 원래 DAW의 보류를 PASS로 바꾸지 않습니다. 오프라인 내보내기나 소스 검토도 실제 호스트 커서 시험을 대체하지 않습니다. 위에 인용한 CI는 이 32 kHz 커서 경계의 실행 증거가 아닙니다.

## 3. 좁은 범위에서의 편집 (CI 확인 항목, 짧게 확인)

- [ ] **가장자리 노드:** Band 1을 +18 dB로 두고 `+/-6 dB`를 고르면 노드가 그래프 위 가장자리에 붙어 보이고 클릭으로 선택됩니다.
- [ ] **실제 값 기준 드래그:** 그 노드를 Alt를 누른 채 옆으로 드래그하면 게인은 +18 dB 그대로이고 주파수만 바뀝니다. +6 dB로 튀지 않습니다.
- [ ] **세밀한 조정:** 좁은 범위에서는 같은 마우스 이동이 더 작은 dB 변화가 됩니다. Shift 미세 조정도 정상입니다.
- [ ] **밴드 추가:** 빈 곳을 더블클릭하면 커서 위치의 주파수와, 현재 범위 기준 dB로 밴드가 생깁니다.

## 4. 호스트 상태와의 분리

표시 범위는 Freeze·PEAK와 같은 **에디터 내부 화면 상태**입니다. 파라미터, 프리셋, A/B, Undo, 저장 상태에 들어가지 않습니다. 범위 유지는 **같은 에디터가 살아 있을 때**의 기준이며, 새 에디터는 ±24로 시작합니다. 다음 항목은 자동화를 끈 기준 프로젝트에서 시작하고 자동화 시험만 별도 사본에서 수행합니다.

- [ ] **프로젝트 수정 표시:** 에디터를 열고 기준 프로젝트를 저장한 뒤 범위만 바꿉니다. 범위 변경만으로 소리 파라미터 변경이 생기지 않아야 합니다. 수정 표시가 생기면 창 열기/닫기만 한 대조군과 비교하고 호스트 UI 메타데이터인지 기록합니다. 원인을 구분하지 못하면 보류이며, 표시만으로 DSP 변경이나 성공을 단정하지 않습니다.
- [ ] **플러그인 EQ Undo/Redo:** GAIN을 +6 → +3 dB로 한 번 편집한 뒤 ±6으로 전환합니다. EQ 패널의 UNDO/REDO가 게인을 +6/+3으로 되돌리고 범위는 ±6으로 유지되는지 확인합니다. 범위만 바꿨을 때 버튼 상태·작업 설명은 그대로여야 합니다.
- [ ] **호스트 Undo:** 먼저 DAW 자체 Undo 메뉴/이력 창에서 EQ 파라미터 편집이 실제 기록·복원되는지 대조합니다(플러그인에 포커스가 있는 Ctrl+Z는 구분하지 못하므로 쓰지 않습니다). 지원되는 호스트에서 EQ 편집 → 범위 변경 → DAW Undo/Redo를 수행하고 EQ 값만 복원되는지 확인합니다. 에디터가 유지되면 범위도 유지되어야 합니다. 호스트가 에디터를 재생성하면 ±24가 정상입니다. 파라미터 Undo 미지원/기록 불가면 이 항목은 보류이며 플러그인 UNDO의 성공으로 대체하지 않습니다. 범위 자체의 Undo 항목이나 추가 파라미터 변경은 없어야 합니다.
- [ ] **오토메이션 기록:** 별도 사본에서 기존 Band 1 GAIN 레인을 준비합니다. Touch/Latch/Write 중 호스트가 지원하는 모드로 실제 GAIN 편집이 기록되는지 먼저 확인하고, 기록을 지운 동일 초기 상태에서 같은 구간을 범위 전환 없이/있이 두 번 기록해 비교합니다. 범위 전환으로 새 파라미터·제스처·추가 값 변화가 생기면 FAIL입니다. Write 모드가 원래 쓰는 일정한 값/기존 레인은 실패가 아니며, 범위를 바꾸지 않은 대조군과 차이가 없어야 합니다.
- [ ] **오토메이션 재생:** Read 모드에서 GAIN을 0 → +18 → 0 dB로 재생하며 ±24/±6을 전환합니다. 같은 시점의 밴드 GAIN과 호스트 레인 값은 일치하고, 화면 밖 노드는 가장자리에 고정되어야 합니다. 소리·파라미터는 자동화를 따라 변하되 **범위 전환이 추가 변화를 만들지 않아야** 합니다. 외부 EQ 자동화는 플러그인 EQ Undo 이력을 무효화할 수 있으므로 그 상태를 실패로 보지 않습니다.
- [ ] **A/B·프리셋:** 서로 다른 EQ 값의 A/B, 공장 프리셋, 호스트 프리셋을 각각 준비해 로드합니다. 같은 에디터에서는 값이 바뀌어도 범위가 유지되어야 합니다. 호스트가 에디터를 재생성한 경우는 ±24 초기화를 별도로 기록합니다. 상태 복원으로 플러그인 EQ Undo 이력이 초기화되는 것은 정상입니다.
- [ ] **저장·완전 재시작:** Tone EQ는 Bell/1 kHz/+6 dB, Final EQ는 구별 가능한 다른 주파수·게인·활성 상태를 설정하고 값을 기록합니다. 화면 범위를 Tone ±6, Final ±12로 두고 프로젝트를 저장합니다. 프로젝트를 닫고 **DAW 프로세스까지 정상 종료**한 뒤 같은 파일을 다시 엽니다.
  - 기준: 두 EQ의 필터·주파수·게인·Q·활성/점유 상태와 저장된 자동화는 복원되고, 새 에디터의 두 범위는 모두 ±24입니다. 저장 당시 Freeze/PEAK 프레임은 복원 대상으로 요구하지 않습니다. 단순 창 숨김/재표시는 이 저장 복원 시험을 대신하지 않습니다.
- [ ] **인스턴스 독립:** 같은 세션의 플러그인 인스턴스 두 개는 범위가 서로 독립입니다. 한 인스턴스 안의 Tone EQ와 Final EQ도 서로 독립입니다.
- [ ] **소리 불변(통제된 비교):** 범위가 바뀌는 동안 파라미터가 그대로인지 우선 확인합니다. null 비교는 변조·노이즈·랜덤/시간 의존 효과·디더·정규화·Auto Set을 끄고, 같은 초기 상태·입력·프리롤·렌더 설정으로 A1(범위 고정), A2(범위 고정 반복), B(범위만 변경)를 준비합니다. 호스트가 바운스 때 에디터를 재생성하면 두 렌더가 모두 기본 범위가 될 수 있으므로, 범위 변경을 실제 수행한 실시간 녹음도 함께 기록합니다. A1/A2가 상쇄되는 조건에서 A1/B도 상쇄되어야 합니다. 대조군 자체가 상쇄되지 않으면 원인을 분리하기 전까지 보류입니다.

## 5. 권장 호스트 조합

현재 수행 우선순위는 Windows입니다. macOS 실기 환경은 미확보이므로 해당 항목은 보류로 남기며 Windows 결과나 macOS CI 통과로 대체하지 않습니다. DAW/장치별 32 kHz 지원은 확인 전까지 가정하지 않습니다.

| 환경·포맷 | 수행 범위 | 현재 실행 조건/한계 |
|---|---|---|
| Windows · 설치된 Reaper 또는 Cubase · VST3 | 0~4번 우선 수행 | 보유 호스트/장치에서 실행. 32 kHz·Undo·팝업 유지 경로는 각각 지원 확인 |
| Windows · Standalone | 메뉴·표시·Freeze·새 실행 초기값, 지원 시 32 kHz 보조 시험 | DAW Undo·트랙 삭제·호스트 자동화·프로젝트 저장은 해당 없음. VST3 수용의 대체 아님 |
| Windows · Pro Tools · AAX | 실제 로드 가능한 빌드로 0~4번 별도 수행 | Pro Tools 판/버전, Developer 또는 retail 여부와 AAX 서명 상태를 기록. 개발 환경 결과는 그 환경에 한정. 배포 수용은 서명된 배포 빌드의 retail 로드 성공 후 판정. 로드 불가면 보류 |
| macOS · Logic Pro AU / Live VST3 또는 AU | 0~4번 + Ctrl 클릭·트랙패드·Retina | **macOS 실기 필요, 현재 보류**. 포맷별 결과 분리 |
| macOS · Pro Tools · AAX | 위 AAX 시험 + macOS 입력/배율 | **macOS와 AAX 환경 모두 필요, 현재 보류** |
| Linux · Reaper/Bitwig VST3 또는 Standalone | 확보 시 해당 범위 추가 확인 | Windows/macOS/AAX 결과를 대체하지 않음 |

## 우선순위

시간이 부족하면 Windows VST3에서 다음을 먼저 합니다. 상태별 문자열은 CI가 확인했지만 아래의 실제 호스트 통합은 별도입니다.

1. 1번의 **메뉴가 열린 채 에디터 닫기**
2. 2번의 **상태별 레벨 표시** 표
3. 4번의 **호스트 Undo**, **저장·다시 열기**, **오토메이션 기록**

## 결과 기록

- [ ] 항목·EQ 뱅크마다 PASS / FAIL / 보류 / 해당 없음, 빌드 SHA, 호스트·포맷·OS, 실제 레이트, 조작 순서, 기대값·관측값, 증거 경로를 적습니다. 보류에는 이유와 재시험에 필요한 환경을 적습니다.
- [ ] 메뉴 수명 시험은 팝업 취소와 에디터 파괴의 순서를 볼 수 있는 녹화, 나이퀴스트 시험은 레이트와 경계 양쪽 수치, Undo/자동화는 호스트 이력·레인, 저장 복원은 전후 EQ 값을 남깁니다. FAIL이면 크래시 로그 등 해당 증거를 첨부합니다.
- [ ] 총평은 `자동 CI 확인`, `Windows 실제 호스트 확인`, `macOS 보류`, `AAX 환경별 확인/보류`, `32 kHz 경계 확인/보류`로 나눕니다. 미실시 항목은 통과 수에 포함하지 않습니다.
