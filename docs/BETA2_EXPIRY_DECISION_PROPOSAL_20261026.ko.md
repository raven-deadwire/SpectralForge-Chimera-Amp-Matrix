# 1.3.2-beta.2 만료일 결정안 — 2026-10-26 KST

P0 **베타 수명주기**의 첫 항목인 "beta.2 전용 만료일 결정"을 위한 안입니다. **이 문서는 승인이 아닙니다.** 소유자가 날짜를 승인하기 전까지 `Validation/beta-lifecycle-policy.json`은 바꾸지 않습니다.

## 1. 지켜야 할 규칙 (BETA_LIFECYCLE.md)

- 만료일은 **버전마다 따로 승인**합니다. beta.1의 승인(`2027-02-11 23:59 KST`)은 `1.3.2-beta.1`에만 적용됩니다.
- 새 버전은 기존 날짜나 90/120/180일 같은 기간을 **자동으로 물려받지 않습니다.** 새 버전 소스에 옛 정책이 남아 있으면 빌드·배포가 거부됩니다.
- 승인 전 정책은 `expires_at_utc: null`, `expiry_approved: false`이고, 이 상태의 빌드는 배포 대상으로 만들 수 없습니다.
- UTC가 기준이고 KST는 +09:00으로 계산합니다. 경고는 만료 14일 전부터, 이미 열린 인스턴스는 닫힐 때까지 소리가 납니다. 만료 뒤 새로 연 인스턴스는 출력만 무음이고 상태·프로젝트는 그대로 저장·복원됩니다.
- 재빌드·재설치로 기간이 다시 시작되지 않습니다.

## 2. 판단 기준

| 기준 | 내용 |
|---|---|
| beta.1보다 짧아지지 않음 | beta.1 사용자가 beta.2로 업데이트했는데 만료가 당겨지면 안 됩니다. 따라서 **2027-02-11 이후**여야 합니다 |
| beta.1과 비슷한 수명 | beta.1은 공개(10/18 01:51 KST)부터 만료까지 **116일**이었습니다 |
| 다음 베타가 나올 시간 | 기존 작업창 기준 1.3.3(11/30–12/25), Náströnd(12/28–1/22), Niflheimr(1/25–2/19), 1.3.4 Room Core(2/22–3/19). 다음 공개 베타가 늦어져도 테스터가 끊기지 않을 여유가 필요합니다 |
| 공개일 불확실성 | beta.2 공개 판정은 11/9–11/13입니다. 공개는 빨라야 11/13, 미달 항목을 고치면 11/16–11/27로 밀립니다 |
| 만료 시점 지원 | 만료가 평일이면 문의·업데이트 대응이 쉽습니다 |

### 권장: B — 2027-03-31 23:59 KST

- beta.1(116일)과 비슷한 수명으로, 베타 운영 방식이 일관됩니다.
- 1.3.3이 기존 작업창(12/25)에 나오면 3개월, 2월로 밀려도 한 달 이상 여유가 있습니다.
- 1.3.4 작업창(3/19) 직후라, 그때까지 다음 베타가 없으면 그 자체가 일정 점검 신호가 됩니다.
- 평일 만료라 대응이 쉽습니다.

### 다시 정해야 하는 경우

- **beta.2 공개가 12/21 KST보다 늦어지면** B의 수명이 100일 밑으로 줄어듭니다. 그때는 공개 전에 날짜를 다시 승인받습니다.
- 공개 뒤에는 만료일을 바꾸지 않습니다. 바꿔야 하면 새 버전(beta.3 등)으로 냅니다.
