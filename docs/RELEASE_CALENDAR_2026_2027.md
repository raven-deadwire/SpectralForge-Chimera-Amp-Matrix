기존 1.3.x 개발 단계 체계를 유지하면서 빠져 있던 공통 FX에 **1.3.3**, Room Core에 **1.3.4**를 배정한다. Room의 2027-02-22–03-19 작업 창은 유지한다. 이후 표기는 1.4.0, 1.5.0, …, 1.10.0, 2.0.0으로 명확히 한다.

Chimera 1.x는 현재의 공개 베타 트랙을 이어가는 계획이다. 공통 FX가 시작되는 1.3.3은 2027년 1–2월에도 베타 순번을 이어가므로, 12월에 정식 1.3.3을 내고 다시 같은 기본 버전의 베타로 되돌리지 않는다. 먼저 안정판을 내거나 긴급 patch가 필요해지면 다음 빈 번호를 배정하고 Room 등 뒤의 예약 번호를 함께 바꾼다.

## 2. 매주 전달하는 흐름

**수요일 테스트 빌드 → 목요일 후보 동결 → 금요일 검증 후 공개 목표**로 운영한다. 기존 매일 15시 구현·평일 17시 검증 예약에서 이 작업을 수행한다. 시간은 한국 기준이며, 주간 표 때문에 별도 인력이나 별도의 모든 제품·OS별 주간 릴리스를 가정하지 않는다.

Chimera의 작은 유지보수와 공통 개선을 주간 기본으로 두고, 독립 제품의 큰 개발은 하나씩 진행한다. 목표는 매주 최소 한 건의 실제 개선과 검증한 빌드다. 보고서·문서·번호 변경만으로 완료하지 않는다. 주요 후보가 막히면 독립적으로 검증 가능한 작은 수정을 선택하고, 가능한 후보가 없으면 목표 미달과 복구 계획을 기록한다.

현재 Chimera 공개 publisher는 Windows/macOS/Linux 패키지를 모두 요구한다. Windows 테스트본 하나만 생긴 상태를 세 OS 공개 완료로 표시하지 않는다. 필수 공개 gate를 통과하지 못한 주에는 실제로 검증된 내부 빌드의 범위와 공개 지연을 구분한다. 새 독립 제품은 각각의 지원 플랫폼 계약과 검증 경로를 구현한다.

첫 두 주를 구체적으로 실행하고 다음 주차는 rolling target으로 관리한다. 2026-11-06부터 매 4주 다음 4주의 범위·소요·의존 일정을 검토한다. 유지보수 행에 적힌 예상 위험은 향후 검토 대상이며 그 결함이 현재 존재한다는 판정은 아니다.

## 5. 두 독립 VST의 제품화와 배포

두 제품 모두 **PRE / AMP / CAB / EQ / SPACE**, AMP 기본 화면, **동시 PRE 4개 교체 슬롯**을 사용한다. Chimera PRE는 5개를 유지한다. 전체 5채널과 13개/14개 앰프 컨트롤을 보존한다. 엔진은 재사용하고 필요한 개선은 공통 모듈에 반영한다.

| 제품 | PRE 라이브러리의 필수 범위 | 제품별 초점 |
|---|---|---|
| Náströnd | BOOST, COMP, PITCH(Octaver/Whammy), WAH, MODULATION(Chorus/Phaser) | 기타 BOOST와 앰프 입력의 상호작용, 채널별 캐릭터, 풀 컨트롤 |
| Niflheimr | COMP, BASS DRIVE, FUZZ, OCTAVER, FILTER, CHORUS | 저역 기반과 Drive/Fuzz 삽입, native LOW/Blend, 채널별 캐릭터 |

모드 수와 동시 슬롯 수를 구분한다. 기존 컴프·EQ·드라이브·공간계를 전면 재작성하지 않는다. 첫 베타에서 미자격인 항목은 표시하고, 전체 필수 라이브러리 완료로 주장하지 않는다. RC에서는 확정 필수 범위의 구현·검증을 확인한다. Niflheimr의 Blend는 native clean/dirty remainder 조절이며 raw DI bypass나 Matrix LOW DI/AMP가 아니다.

## 8. 공개 완료의 확인 항목

공개할 때마다 포함 기능·변경점, 제품 버전과 소스, 실제 통과한 플랫폼/호스트 범위, 설치 파일·SHA-256, 업데이트/복귀 안내를 남긴다. 실제 파일을 확인한 후 같은 날 또는 다음 날 홈페이지 다운로드·현재 제품 설명·변경 내역을 반영한다. 기존 개인 IR·프리셋·세션을 보존한다.

## 예약 검증 운영

`python Tools/check_release_calendar.py`는 공개 이력 snapshot, 제품별 예약·태그·증가 순서, 연속 금요일과 테스트/후보 날짜, Markdown/JSON 및 로드맵 mirror를 대조한다. `--live`는 GitHub 전체 태그와 공개 release를 페이지 끝까지 읽고 충돌·역행을 추가 검사하며 조회 실패 시 차단한다. `--target-version`은 예약 존재를 확인한다. `chimera_version.py --check-reservation --target-version ...`은 소스의 VERSION/RELEASE_CHANNEL 일치도 요구한다.

PR CI는 세 OS에서 오프라인 계약 검사, 별도 live job에서 원격 중복 검사를 실행한다. publisher는 동일 검사를 최초 배포 준비와 업로드 후 공개 직전에 반복한다. 캘린더는 승인 증거가 아니며 기존 CI·패키지·설치·승인 gate를 대체하지 않는다. 공개 후 해당 행을 `published`로 기록하고 `published_releases`에 태그·소스를 추가한 뒤 다음 예약을 검증한다.
