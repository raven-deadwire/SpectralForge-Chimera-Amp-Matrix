# 44.1kHz 약한 마커 사례 분석 — 2026-10-25 KST

**배경.** 고정 PDC 계약의 새 시드 검증(`TRANSPOSE_T6_PDC_CONTRACT.md`)에서 44.1kHz만 어택 잔차 53.2ms로 실패했다. 기준은 4.5ms였다. 기준을 넘은 16개 이벤트는 모두 한 입력에서 나왔다(기타 A1, 지속음 위 무작위 약한 마커, 시드 26457).

**결론: 주원인은 측정이다. 이 마커들은 어택 지표가 보는 1–8kHz 대역에서 배경보다 0–6dB밖에 높지 않다.**

- 배경은 지속음 고조파가 이 대역으로 새어 든 성분이다. 마커가 배경과 구별되지 않으면 어택 peak는 아무 데나 잡힌다.
- 엔진 쪽 원인도 있다. 업시프트 접합이 이 대역의 배경을 최대 6.4dB 올린다. 그래서 배경 수준의 마커에서는 접합 잡음이나 다시 읽힌 마커 꼬리가 peak로 잡힌다.
- 이벤트별로 '마커가 배경보다 충분히 높은가'를 보면 문제가 정확히 갈린다. 기준을 넘은 이벤트 320개는 모두 SNR 6dB 미만이었다. 6dB 이상인 이벤트 12,620개는 하나도 넘지 않았다.

**처리.** 지난 판정(PDC 44.1kHz FAIL, T1 기록)은 바꾸지 않는다. 지표 보완안은 기본값이 꺼진 옵션으로만 넣었고, 다음 사전 등록 검증부터 적용을 제안한다.

엔진 코드와 제품 `Source/`는 바꾸지 않았다. 측정은 합성 입력만 썼다.

## 1. 실패한 입력의 이벤트 추적

`Tools/TransposeNext/SpliceTrace.cpp`로 추적했다. 엔진을 한 샘플씩 처리하면서 고역 경로 접합, 저역 경로 접합, onset 재정렬의 샘플 위치를 기록하는 도구다. v3는 블록 분할과 무관하므로 출력은 TransposeProbe(block 128)와 비트 동일하다(6개 조건 모두 확인).

**이벤트 SNR 정의.** 이벤트 뒤 10ms 안의 1–8kHz 2ms RMS 최댓값을, 이벤트 20–3ms 전의 최댓값과 비교한다. 3ms 간격을 두는 이유는 중심 정렬 창과 위상 지연 없는 필터가 어택 에너지를 앞으로 퍼뜨리기 때문이다. 간격 없이 재면 정상 피킹도 1dB 근처로 나온다.

**44.1kHz 결과.** 16개 마커의 SNR은 모두 0.0–5.7dB였다.

| 이벤트 유형 | 원음 peak 지연 | 출력 쪽 |
|---|---|---|
| SNR 0–0.4dB (3, 6, 12번) | 5.2 / 7.0 / 6.2ms. 이벤트가 아니라 배경에 걸린다 | 다운시프트 잔차가 음수(−4 ~ −6ms)로 나온다 |
| 업시프트 큰 값 (+1반음 55.7·46.4ms, +2반음 38.1·29.2ms 등) | 1ms 안팎 | 출력 peak가 두 위치 중 하나에 있다 |

업시프트 출력 peak가 있는 두 위치는 다음과 같다.

- **고역 접합 순간(0.2–5ms 차이):** 접합 잡음이 마커보다 크다.
- **접합 16–38ms 뒤:** 접합으로 읽기 위치가 뒤로 돌아가 마커 꼬리를 다시 읽은 것으로 보인다.

**48kHz.** 같은 시드에서 같은 현상이 나온다. 다만 원음 자체의 peak 지연이 45ms인 이벤트가 있어서 그 입력 전체가 T1 유효 기준(모든 이벤트 ≤ 10ms)에서 빠졌다. 44.1kHz와 48kHz의 판정 차이는 이 유효 기준의 우연이다.

## 2. 무작위 마커 전체

**대상.** 3 표본률 × 3 악기 × 시드 11개(지금까지 쓴 holdout 시드 전부) × 반음 4, v3로 렌더했다.

**접합 잡음.** 마커 없는 같은 지속음(12배음)에서 1–8kHz 배경 최댓값을 출력과 원음으로 비교했다.

| 반음 | 출력 / 원음 |
|---|---|
| −2 | −6.7 ~ −5.4dB |
| −1 | −3.2 ~ −2.7dB |
| +1 | −2.1 ~ +2.3dB |
| +2 | −1.0 ~ **+6.4dB** |

다운시프트는 배경을 낮추고, 업시프트(특히 +2)는 접합 잡음으로 배경을 올린다. 배경 수준의 마커에서는 이 차이로 peak가 바뀐다. 실제 어택에서는 영향이 없다(아래 3).

**입력 종류별 이벤트 SNR.** 위 정의로 쟀다.

| 입력 | 이벤트 | SNR 최소 / p5 / 중앙 | SNR 10dB 미만 | 원음 peak > 10ms |
|---|---:|---|---:|---:|
| 무작위 마커 | 1,584 | −7.4 / −1.1 / 29.4dB | **528** | 127 (모두 SNR < 10dB) |
| 마커 0.004 (지속음 위) | 144 | 16.2 / 18.3 / 51.8dB | 0 | 0 |
| 마커 0.001 (지속음 위) | 144 | 3.2 / 6.5 / 39.6dB | 45 | 0 |
| 강약 교대 | 144 | −8.3 / −4.7 / 21.0dB | 52 | 0 |
| riff75 | 144 | 8.1 / 10.2 / 20.9dB | 6 | 0 |
| 랜덤 피킹 / 강약 랜덤 | 1,584씩 | 22.2·12.7 / 48.4·43.6 / 67dB | 0 | 0 |
| 긴 음 | 90 | 53.0 / 53.4 / 60.7dB | 0 | 0 |

## 3. SNR과 어택 잔차

**대상.** v3 PDC 측정의 모든 어택 이벤트 13,868개다(기존 시드와 새 시드, L = 2.5ms 보정 후 잔차).

| 이벤트 SNR | 이벤트 | 잔차 > 4.5ms | 잔차 최대 |
|---|---:|---:|---:|
| < 6dB | 1,248 | **320** | 68.8ms |
| 6–10dB | 436 | 0 | 2.89ms |
| 10–15dB | 428 | 0 | 2.74ms |
| 15–20dB | 424 | 0 | 2.83ms |
| ≥ 20dB | 11,332 | 0 | 3.08ms |

기존 T1 유효 기준(입력의 모든 이벤트 peak ≤ 10ms)만으로는 SNR이 낮은 입력이 우연히 통과하거나 우연히 빠진다.

**같은 데이터에 이벤트별 'SNR ≥ 10dB'를 더하면 (참고, 판정 아님):**

| | 44.1kHz | 48kHz | 96kHz |
|---|---:|---:|---:|
| 새 시드, L = 2.5ms 잔차 최대 | 3.01ms | 2.92ms | 2.91ms |
| 기존 시드로 L을 다시 고르면 | 2.75ms (잔차 최대 2.65ms) | 2.75ms (2.83ms) | 2.75ms (2.80ms) |

기존 시드로 L을 고를 때도 SNR이 낮은 이벤트가 영향을 줬다.

## 4. 제안 (사전 등록 전 기록)

1. **어택 타이밍 지표(T1, 고정 PDC)에 이벤트별 SNR 기준 추가.**
   - 이벤트 SNR ≥ 10dB인 이벤트만 센다. 기존 입력 단위 유효 기준과 함께 쓴다.
   - 10dB는 데이터상 경계(6dB)보다 보수적으로 잡은 값이다.
   - 마커 입력은 검출 판정(T4: 오검출·누락·저역 재설정)에 그대로 쓴다. 타이밍에서만 뺀다.
2. **적용 방식.**
   - 도구에 기본값이 꺼진 옵션으로 넣었다: `latency_targets.py --event-snr-min`, `pdc_study.py evaluate --event-snr-min`.
   - `latency_targets.py`의 새 결과에는 이벤트별 지연과 SNR(`attack_added_ms`, `attack_event_snr_db`)이 함께 저장된다.
   - 기본 동작과 과거 결과는 그대로 재현된다. 확인: 새 시드 v3 결과 재평가 T1 5.667ms, PDC 잔차 53.24 / 2.92 / 2.91ms로 이전과 같다.
3. **다음 검증.** 아래 세 가지를 사전 등록한 뒤 처음 쓰는 시드로 한 번 실행한다.
   - SNR 기준
   - L(2.5ms 유지 또는 2.75ms 재선택)
   - 잔차 기준
4. **엔진 쪽 (별도 과제).** 업시프트 접합이 1–8kHz 배경을 최대 6.4dB 올리는 문제와, 접합 뒤 마커 꼬리를 다시 읽는 문제가 남아 있다. 실제 어택(SNR ≥ 6dB)의 타이밍에는 영향이 없었다. 실제 DI의 약한 고역 성분(뮤트한 현의 긁힘 등)에서 들리는지는 청취와 실제 DI 검증에서 확인한다.
