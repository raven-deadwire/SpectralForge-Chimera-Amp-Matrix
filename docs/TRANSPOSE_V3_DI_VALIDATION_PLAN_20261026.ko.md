## 1. 대상과 범위

- **candidate:** `corr40-split-v3`(#152·#154 기준 T6 후보). 연구 플러그인·`TransposeProbe`로 실행합니다.
- **product:** 현재 제품 엔진 `PolyPitch`(바꾸지 않음). 청취·DAW에서 비교 기준입니다.
- **v4 / 1.25 ms 절충안은 대상이 아닙니다.** #155에서 연구 자료로만 보관하며, 연구 플러그인의 v4 옵션은 꺼 둡니다.
- 이 계획을 모두 통과해도 **제품 통합은 별도 작업**입니다(§6).

### "2.5 ms"에 대해

2.5 ms는 v3가 DAW에 **보고하는 고정 지연(PDC)** 값입니다. 실제 지연이 아닙니다.
- 어택 실제 추가 지연은 음마다 약 −0.4–5.6 ms로 변하고, DAW가 2.5 ms를 보정한 뒤 남는 잔차를 4.5 ms 안에 두는 것이 목표입니다.
- 저역 onset은 이 보정으로 맞춰지지 않습니다. 합성 입력에서 보정 후에도 0.2–15.4 ms 늦습니다. 이번 실제 DI에서 이 값을 다시 잽니다.

## 5. P0 판정 연결

| 결과 | 기준 | P0 Transpose 처리 |
|---|---|---|
| DI 측정 | T1·T2·T4 PASS(INSUFFICIENT·FAIL 없음), T3 참고값 보고 | 하나라도 FAIL이면 v3 제품 적용 보류 |
| 청취 | 쌍 비교 PASS(선호 ≥ 50%, 속성 점수 기준 충족) | FAIL이면 보류. INSUFFICIENT면 청취 재진행 |
| DAW | D01–D13 모두 기록, D05 Fixed PDC 동작, D06 체감 점수, D12 CPU 초과 없음 | 차단 결함(로드 실패, PDC 불일치, 저장·복원 손실, 지속적 CPU 초과)이 있으면 보류 |
| 종합 | 세 영역 모두 통과 | "v3 제품 통합 후보"로 승격. 통합·회귀 검증은 별도 |

- 통과하지 못해도 결과는 그대로 보고하고, 기준을 사후에 바꾸지 않습니다.
- 이 계획의 결과는 **연구 후보의 외부 수용 증거**입니다. 제품 Transpose가 바뀐 것은 아닙니다.

## 6. 남는 결정 (11/6 이후)

- **제품 통합:** v3가 통과하면 `PolyPitch`를 대체할지, 품질/지연 모드로 둘지 결정하고 통합·회귀·상태 복원·프리셋 영향을 검증해야 합니다. 11/9–11/13 동결 전에 끝나지 않으면 beta.2에 넣을 수 없습니다.
- **beta.2 범위:** v3가 통과하지 못하거나 통합이 늦으면, beta.2는 기존 Transpose를 한계와 함께 내보낼지, Transpose 개선을 다음 판으로 미룰지 결정이 필요합니다. 이 결정은 P0 판정 회의(11/9–11/13)에서 합니다.
