# SYNTH: wavetable import

Status: implemented on the `claude/synth-wavetable-import` branch, stacked on
`claude/synth-presets`. Measured by `ChimeraSynthTests` on Linux. Not tried in
a DAW, and not on Windows or macOS. No wavetable file made by Serum or any
other product was tried: the test files were generated by the tests.

## Why

The owner's direction for SYNTH is a synth in the class of Serum or ArgWave 3.
Until now an oscillator played the classic shapes or one of nine built-in
wavetables. This step lets each oscillator play a wavetable read from an
audio file.

## What it does

- Each oscillator (A, B, C) can hold one imported wavetable.
- The file is cut into frames of one cycle each. POSITION moves through the
  frames and blends neighbours, as with a built-in table. The warp and the
  matrix's Wave target work the same way.
- A file can be WAV, AIFF, FLAC or OGG (what the sample oscillator reads).
  Stereo is mixed to mono. The file's sample rate does not matter.
- A table holds at most 64 frames.
  - A file with more frames: 64 evenly spaced frames are kept, the first and
    the last among them.
  - Beyond 256 frames the file is not read.
- Every frame is stored like a built-in frame: 2048 samples, band-limited at
  21 levels, so a high note does not alias.
- Level: DC is removed. The loudest frame peaks at full scale and the others
  keep their level against it.

## Cutting the file into frames

Chosen in the oscillator's table menu.

- **Import wavetable...** (Auto):
  1. the frame size a `clm ` chunk in a WAV file names (Serum writes one);
  2. else 2048 samples when the length is a multiple of 2048;
  3. else the whole file as one cycle when it is 8192 samples or shorter;
  4. else 2048 samples, with what follows the last whole frame left out.
- **Import with frame size:** 256, 512, 1024 or 2048 samples, or **One
  cycle** (the whole file, 16 to 16384 samples).
- A frame that is not 2048 samples long is converted to 2048 with its
  harmonics kept (up to 1023).
- When frames or samples were left out, a message says how many.
- Refused, with a message and without changing the oscillator: a file that
  is not audio, is shorter than one frame, is silent, or is too long for One
  cycle.

## On the page

- The table menu in each oscillator's header lists the built-in tables, then
  `<name> (imported)` when the oscillator has one, the import commands and
  **Remove imported table**.
- Importing switches the oscillator on, to Wave mode and to its imported
  table.
- Choosing a built-in table leaves the imported one in the oscillator;
  choosing `<name> (imported)` plays it again.
- The display shows the table's name, its number of frames and the position.
- Dropping a file on the display still loads it as a sample, not as a table.

## Parameters and compatibility

- Three parameters appended at version hint 42, after the effect rack:
  `synthOscAImported`, `synthOscBImported`, `synthOscCImported` (off / on).
  Automatable. Off, the default, is the oscillator as it was (tested sample
  for sample, also with a table present).
- On without a table in the oscillator: the built-in table or the classic
  shapes play, as if it were off.
- No earlier parameter changed. The table menu's parameter (`synthOscATable`
  ...) still holds the built-in table.
- A patch or a preset carries the three switches (187 parameters now), but
  not the table itself.

## In the project

- The imported tables are saved with the project, like samples: they belong
  to the project, not to an A/B slot.
- What is saved is the frames as imported (2048 samples each, 32-bit); the
  table is rebuilt from them on load and comes back exactly (tested).
- One 64-frame table adds about 0.7 MB to the saved project.

## Not done

- Presets do not carry imported tables. A preset saved with an imported
  table plays the built-in table on a project that has none.
- No library of imported tables: a table lives in the project it was
  imported into, one per oscillator.
- No drag and drop for tables, and no export.
- No more than 64 frames, and no choice of which frames are kept.
- No editing of a table (drawing, FFT editing, sorting, crossfading frames).
- No frame size other than those listed, and no detection of the cycle
  length from the audio: a recording that is not already cut into equal
  cycles does not become a useful table.
- Frames are not aligned in phase with each other.
- Formats other than audio files (`.vitaltable`, `.fxp` and so on) are not
  read.
- A table can be swapped while a note sounds; the oscillator is silent for
  the one block the swap meets, as with samples. Not measured by ear.
- DE / KO manual text is not written.

## Measurements

From `ChimeraSynthTests` on Linux (x86-64), 48 kHz, this branch.

- Four frames holding harmonics 1 to 4, A3: at POSITION 0 % 880 Hz is 322 dB
  below 220 Hz; at 100 % 220 Hz is 329 dB below 880 Hz; at 50 % 440 Hz and
  660 Hz are level (-13.96 dBFS each) and 220 Hz is at -191 dBFS.
- Switch on without a table, and switch off with a table: largest sample
  difference from the oscillator before this change 0.
- An imported saw (one 2048-sample frame): at C8 harmonic 4 at -12.04 dB
  (-12.04 for a saw), folded harmonics 6 and 7 at -169 and -175 dB; at A3
  harmonic 2 at -6.02 dB and harmonic 60 at -35.58 dB (-35.56).
- A cycle of 256 samples converted to 2048: largest error 2.0e-7; of 600
  samples: 1.4e-7.
- Auto: eight frames of 2048 read as eight; three frames plus 10000 samples
  read as seven with "1808 samples ... left out"; 600 samples read as one
  cycle; 4096 samples read as two frames; a `clm ` chunk naming 1024 read as
  four frames of 1024.
- 100 frames: 64 kept, and the table's last frame is the file's last.
  300 frames: the first 256 read, 64 kept.
- Importing 256 frames of 2048 samples: 51 ms (one run, this machine).
- Project: 682 KiB more with one 64-frame table; largest difference after
  save and restore 0. A project without tables clears them. A damaged table
  entry is ignored.
- Page: the menu shows the imported table, a built-in table, the imported
  table again and Remove, each with the oscillator's switch following; a
  refused import leaves the oscillator as it was.
- CPU was not measured. The table is read the same way as a built-in one.
