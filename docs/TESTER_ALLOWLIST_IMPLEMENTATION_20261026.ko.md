# 짧은 오프라인 테스터 코드: 발급 도구와 제품 검증 분리

## 변경 범위

PR #186의 저장·삭제·입력 방어를 유지한 후속 구현이다. #181의 짧은 `CHT1-<NAME>-<6자리>` 형식은 유지하지만, 제품에 HMAC 발급 비밀값을 넣던 구조를 제거한다. 소유자 도구는 무작위 코드를 비공개 파일에 만들고, 별도로 승인한 전체 코드의 SHA-256 확인값만 빌드에 포함한다.

- 제품에는 발급 키·비밀값·코드 생성기가 없다.
- 전체 정규화 코드에 이름까지 결합하므로 다른 이름에 같은 6자리를 옮겨도 통과하지 않는다.
- PR 이외의 릴리즈 후보는 별도 승인된 비어 있지 않은 확인값 목록이 없으면 기존 gate를 대체하는 검사에서 차단된다.
- 확인값만 있는 공개 manifest를 CMake에서 엄격히 검사한다. 빈 목록은 빌드 가능하지만 모든 코드를 거부한다.
- 실제 코드 원문은 Git 체크아웃 밖에서 독점 생성하며 POSIX 0600으로 저장한다. 발급·검증 CLI는 코드 원문을 출력하거나 명령 인자로 받지 않는다.
- 미리 포함한 여유분의 배정에는 새 빌드가 필요 없지만 이름 변경·새 코드 추가에는 목록 갱신과 새 빌드가 필요하다.
- 이전 HMAC 코드는 자동으로 신뢰하지 않는다. 같은 코드 원문을 유지하려면 별도로 승인하여 확인값 목록에 이관해야 한다.

## 정책과 보안 한계

무기한·후속 모든 베타 권한, 코드 공유 허용, 버전별 만료, 이미 실행 중인 인스턴스의 오디오 유지, 잘못된 빌드 메타데이터 거부는 유지한다. 후속 베타는 승인된 확인값을 보존해야 한다.

**6자리 Base32는 약 30비트다.** 공격자는 공개 확인값으로 오프라인 대입을 수행할 수 있다. 발급 비밀 추출로 임의 이름의 코드를 계산하는 구조는 제거하지만, 이 짧은 형식을 강력한 라이선스 보호라고 주장하지 않는다. 코드 공유·바이너리 패치·오프라인 구버전의 즉시 회수도 해결하지 않는다.

이번 구현의 production manifest는 비어 있다. 실제 발급, 기존 코드 조회·이관, 운영 목록 등록, 메일 수정·발송, 계정/저장소 secret 설정, 병합·배포는 수행하지 않았다. 시험은 공개된 더미 데이터만 사용했다.

## 로컬 검증

- JUCE 8.0.8의 실제 `juce_core`/`juce_cryptography`와 새 C++ 검증기를 컴파일하여 입력·이름 결합·변조·미등록·이전 HMAC 거부·빈 목록·저장/삭제/권한·실행 중 만료 latch 검사를 통과했다.
- C++/Python 교차 입력 검사를 포함한 `Tools/test_tester_code.py`: 13/13 통과.
- `Tests/test_tester_allowlist_build.py`: 11/11 통과. 잘못된 JSON/필드/크기/중복/문자 거부, 공개 header 생성, 원문/발급 secret/도구의 제품 경계 검사.
- `Tools/test_beta_lifecycle.py`: 13/13 통과. `ChimeraBetaLifecycleTests` 직접 빌드/실행 통과.
- `Tools/test_preset_maintenance.py`: 23/23 통과.
- `Tools/test_publish_release.py`: 35/35 통과.
- `Tools/test_release_scope.py`, `Tools/test_ctest_validation.py`: 통과. 기존 release 차단 조건은 완화하지 않았다.
- `Tests/test_packaging_version.py`: 24 통과, Windows 전용 3개 건너뜀.
- `git diff --check`: 통과.

전체 product 구성은 로컬 환경의 FreeType/X11 개발 헤더(`ft2build.h`, `X11/Xlib.h`) 부족으로 juceaide 단계에서 막혔다. 이 환경에서 전체 processor/editor, 실제 DAW, 설치/업데이트 및 Windows/macOS 실행을 통과했다고 주장하지 않는다. 수정된 processor 회귀 검사는 기존 CI 대상에 남겨 두었다.

최종 커밋의 GitHub 전체 빌드·베타 수명주기·패키징 결과는 별도로 확인해야 한다. Draft PR이나 국소 검증은 운영 자격 증명 등록 또는 릴리즈 승인이 아니다.
