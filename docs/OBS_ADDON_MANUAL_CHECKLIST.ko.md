# Chimera OBS 필터 — 실제 PC 수동 확인 체크리스트

CI의 실제 OBS 앱 자동 시험(`OBS/tests/obs_*_test.py`, `obs-addon.yml`·`obs-long-recording.yml`)으로는 확인할 수 없는 것을
**실제 PC, 실제 오디오 장치, 사람의 화면 조작**으로 확인하기 위한 목록입니다. 계획 C–F단계([OBS_ADDON_PLAN.md](OBS_ADDON_PLAN.md))의
"수동 확인 전" 항목과 [OBS/README.md](../OBS/README.md)의 **미실행** 목록을 이 문서로 확인합니다.

- **CI가 이미 확인한 것:** 필터 로딩·녹화·상태 저장과 복원, 다중 인스턴스·붙여넣기, 사용자 IR, 에디터 창 열기, 44.1 kHz 모노·48 kHz 5.1,
  처리 지연과 A/V 싱크, OBS 밖 Chimera와의 표본 단위 일치, 중단·재개 꼬리 제거, 다른 샘플레이트·배치로 재시작, 처리 실패 시 무음/원음 통과,
  Linux의 에디터 안 편집, CI 가상 머신 1시간 녹화. 이 목록은 이를 반복하지 않습니다.
- **판정:** 항목마다 **PASS / FAIL / 보류**를 적고, 미실행은 **보류(미실행)**로 유지합니다. FAIL이면 재현 방법과 OBS 로그(도움말 → 로그 파일)를 함께 남깁니다.
- **결과 기록:** 전용 OBS 애드온 시험은 [#131](https://github.com/raven-deadwire/SpectralForge-Chimera-Amp-Matrix/issues/131)에 아래 0번의 기록과 함께 남깁니다.
- **별도 추적:** atkAudio + Chimera VST3 호환 시험은 [#130](https://github.com/raven-deadwire/SpectralForge-Chimera-Amp-Matrix/issues/130)에 기록하며, 두 경로의 결과를 서로 승계하지 않습니다.
- **CI 자동시험 기록:** 실행 URL·attempt·시험 소스 SHA·OS/OBS 버전·job/항목·판정을 실제 PC 수동시험과 분리해 기록합니다. 이전 SHA의 CI 통과를 현재 HEAD의 통과로 표시하지 않습니다.
- **실제 PC 수동시험 기록:** 확인일·0번의 환경/모듈 정보·항목별 판정·증거를 남깁니다. Windows·macOS 에디터 내부 마우스 조작과 실제 장비 시험은 직접 수행하기 전까지 보류(미실행)이며, CI 통과로 PASS 처리하지 않습니다.
- 아래 화면 문구는 한국어 OBS 기준입니다(영어 OBS는 `OBS/data/locale/en-US.ini`의 같은 항목).

## 0. 준비와 기록

- [ ] **환경 기록:** OS와 버전, CPU·GPU, 메모리, OBS 버전, 오디오 장치(입력·출력)와 드라이버, OBS 설정 → 오디오의 샘플레이트·채널.
- [ ] **모듈 기록:** OBS 로그의 `[chimera-obs] module <버전> (source <커밋>), built and tested for OBS <버전>, running OBS <버전>` 줄과
  필터의 `loaded SpectralForge Chimera <버전> ... from <경로>` 줄을 그대로 옮깁니다.
- [ ] **버전 경고:** 실행 중인 OBS의 주 버전이 빌드 대상과 다르면 로그에 경고가 있고, 필터 속성 창에
  "실행 중인 OBS 버전에서는 시험하지 않음:" 문구가 보입니다. 같은 주 버전이면 둘 다 없습니다.
- [ ] **기타 DI:** 기타(가능하면 베이스도)를 오디오 인터페이스의 하이 임피던스 입력에 연결합니다. 모니터 볼륨은 확인하는 동안 고정합니다.

## 1. 설치·업그레이드·제거 (실제 PC)

근거: [OBS/README.md](../OBS/README.md)의 설치 절. CI는 가상 머신의 설치 위치·소유 파일·제거만 확인합니다.

- [ ] **Windows Setup:** OBS 항목이 OBS가 설치된 PC에서 미리 선택되고, 설치 뒤 OBS의 필터 목록에 "SpectralForge Chimera"가 보입니다.
- [ ] **macOS PKG:** OBS 항목을 고르면 로그인한 사용자의 OBS 플러그인 폴더에 설치되고 OBS가 필터를 로드합니다.
  지금 PKG는 서명·공증 전이라 Gatekeeper가 막을 수 있으니, 어떤 경고가 나왔고 어떻게 열었는지 적습니다.
- [ ] **Linux DEB/TAR:** TAR 설치 때 OBS 필터 설치 여부를 묻고, 설치하면 OBS(30 이상)가 필터를 로드합니다.
- [ ] **OBS 실행 중 보호:** OBS를 켜 둔 채 설치·제거를 시작하면 OBS를 닫으라는 안내와 함께 멈추고, 파일을 바꾸지 않습니다.
- [ ] **업그레이드:** 필터를 쓰는 장면이 있는 상태에서 새 버전을 설치하고 OBS를 열면, 장면·필터 상태(프리셋 소리)가 그대로입니다.
- [ ] **제거:** 제거 뒤 OBS 플러그인 폴더에 Chimera 필터 파일이 남지 않고, 사용자 장면·프리셋·IR 파일은 남아 있습니다.
  필터를 쓰던 장면을 열어도 OBS가 오류 없이 시작합니다(그 소스의 필터 목록에 어떻게 보이는지 적습니다).

## 2. OBS 화면에서의 필터 조작

CI는 obs-websocket과 Lua 스크립트로 필터를 다루며 화면을 누르지 않습니다.

- [ ] **추가:** 오디오 소스(마이크/기타 입력) → 필터 → 오디오 필터 `+` → "SpectralForge Chimera"로 추가하면 소리가 바로 처리됩니다.
- [ ] **속성 창 상태:** "상태"가 "처리 중", "처리 지연 (OBS가 자동 보정하지 않음)"에 샘플·ms 값, "실시간 처리"에 부하·끊김·처리하지 못한 블록이
  보입니다. "실시간 통계 초기화"를 누르면 값이 0부터 다시 쌓입니다.
- [ ] **입력:** "입력"을 스테레오 / 왼쪽 채널을 양쪽으로 / 오른쪽 채널을 양쪽으로 / 합으로 바꿀 때마다 들리는 쪽이 설명대로 바뀌고 클릭이 없습니다.
- [ ] **필터 켜기·끄기:** 필터의 눈 아이콘으로 끄면 원음, 켜면 처리음이 들립니다. 켤 때 이전 소리의 꼬리(딜레이·리버브)가 다시 나오지 않습니다.
- [ ] **복사·붙여넣기:** 필터를 오른쪽 클릭 → 복사, 다른 소스에 붙여넣기(필터 하나·전체 둘 다)를 하면 같은 소리가 나고, 한쪽을 바꿔도 다른 쪽은 그대로입니다.
- [ ] **장면 컬렉션:** 장면 컬렉션을 내보내고 다른 PC(Chimera 설치)에서 가져오면 같은 소리가 납니다. 사용자 IR 파일이 없어도 됩니다.

## 3. 에디터 창 (Windows·macOS)

Linux의 에디터 안 편집은 `obs_editor_edit_test.py`가 자동으로 확인합니다.

- [ ] **열기·다시 올리기:** "Chimera 에디터 열기"를 누르면 창이 OBS 위에 열리고, 다시 누르면 같은 창이 앞으로 옵니다(두 번째 창이 생기지 않음).
- [ ] **에디터 안 편집:** 에디터에서 노브·프리셋을 바꾸면 소리가 즉시 바뀌고, 에디터를 닫고 OBS를 다시 시작해도 바뀐 소리가 유지됩니다.
- [ ] **편집 중 녹화·방송:** 에디터를 연 채로 녹화해도 드롭아웃·클릭이 없습니다(OBS 통계 창의 렌더링·인코딩 지연 프레임 함께 기록).
- [ ] **연 채로 종료:** 에디터를 연 채 OBS를 종료해도 정상 종료하고, 다음 실행에서 소리가 같습니다.
- [ ] **고해상도 화면:** 배율 150%·200% 모니터와 두 모니터 사이로 창을 옮겨도 글자·노브가 깨지지 않고 마우스 위치가 맞습니다.

## 4. 실제 오디오 장치

CI는 미디어 파일만 재생합니다.

- [ ] **지연 체감:** 기타를 치며 OBS 모니터링(모니터만 / 모니터와 출력)으로 들을 때 처리 지연(속성 창 값, 기본 42 샘플)이 연주에 방해되지 않습니다.
  OBS 자체 모니터링 지연과 구분해 적습니다.
- [ ] **영상 싱크:** 카메라와 함께 녹화하면 손과 소리가 맞습니다. 어긋나면 소스의 고급 오디오 속성 → 싱크 오프셋 값과 함께 기록합니다.
- [ ] **장치 분리·재연결:** 녹음 중 오디오 인터페이스 USB를 뺐다 다시 꽂으면 OBS가 장치를 되찾은 뒤 처리음이 다시 나오고,
  이전 꼬리가 다시 나오지 않습니다. 로그의 세션 합계에 "resumed after silence"가 늘어납니다.
- [ ] **OBS 샘플레이트 변경:** 설정 → 오디오에서 44.1 kHz ↔ 48 kHz를 바꾸고 OBS를 다시 시작하면 같은 소리(프리셋)로 처리됩니다.

## 5. Chimera를 처리할 수 없을 때

CI는 없는 번들 경로로 확인합니다. 여기서는 실제 사용자가 겪을 상황을 확인합니다.

- [ ] **Chimera 제거 후 OBS 시작:** Chimera VST3만 제거(또는 이름 변경)하고 OBS를 열면, 기본 설정에서 그 소스는 **무음**이고
  상태가 "Chimera VST3가 로드되지 않음", 로그에 찾지 못한 경로가 있습니다. 가공되지 않은 소리가 방송에 나가지 않습니다.
- [ ] **원음 통과 선택:** "Chimera가 처리할 수 없을 때"를 "원음 통과"로 바꾸면 같은 상황에서 원음이 들립니다.
- [ ] **복구:** Chimera를 다시 설치하고 "Chimera VST3 번들" 경로를 비우거나 OBS를 다시 시작하면 처리음이 돌아오고 프리셋도 같습니다.

## 6. 장시간 녹화·방송 (실제 장비)

CI는 가상 머신에서 1시간 녹화만 확인합니다([OBS/README.md](../OBS/README.md)의 장시간 녹화 절).

- [ ] **1시간 녹화:** 기타 DI 입력과 카메라로 1시간 녹화합니다. 시작·끝에서 손과 소리가 맞고, 중간에 드롭아웃·클릭이 없습니다.
- [ ] **기록:** OBS 통계 창(CPU, 메모리, 렌더링·인코딩 지연 프레임)과 로그의 `[chimera-obs] ... session total` 줄
  (부하 평균·최대, 실시간 초과 창, 입력 끊김, 처리하지 못한 블록)을 시작과 끝에 적습니다. 처리하지 못한 블록은 0이어야 합니다.
- [ ] **실제 방송:** 비공개 방송(예: 플랫폼의 테스트 스트림)으로 30분 이상 송출해 다시보기에서 소리·싱크를 확인합니다.

## 7. 다른 OBS·Mac

- [ ] **macOS OBS 32.x:** CI 가상 머신에서는 OBS 32.2.2가 필터 없이도 시작 중 종료해 확인하지 못했습니다. 실제 Mac에서 1–3번을 확인합니다.
- [ ] **실제 Intel Mac:** CI는 Apple silicon에서 Rosetta로만 Intel 빌드를 확인합니다. 실제 Intel Mac(macOS 12 이상)에서 1–3번과 6번(짧게 10분)을 확인합니다.
