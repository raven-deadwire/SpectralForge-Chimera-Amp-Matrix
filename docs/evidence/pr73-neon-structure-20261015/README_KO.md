# PR #73 NEON 비용 증가 원인 조사

2026-10-15. PR #74의 독립 비교는 완료된 근거로 유지했다. 이번 작업은 Apple M1의 AppleClang ARM64 어셈블리와 실제 CAB 검증 번역 단위를 조사하고, 원인별 최소 변경을 분리하는 후속 진단이다. PR #73 병합·출시는 보류한다.

## 확인된 구조 차이

1. 원본의 스칼라 C++도 실제로는 자동 벡터화된다. 128-bit NEON 두 묶음으로 **8개 bin**을 처리하고, paired load/store를 사용한다. PR #73은 **4개 bin**씩 처리한다.
2. 실제 CAB 코드의 PR #73은 NEON 저장 뒤 `bins` 멤버를 **4-bin당 두 번 다시 읽는다**. 주소 계산과 다음 반복 조건이 이 읽기에 의존한다. `bins`를 값으로 넘기는 분리 커널만 측정하면 이 문제를 놓친다.
3. 실제 주 반복문의 정적 명령 수는 8-bin 기준 원본 **24개**, PR #73 **46개**다. FMA/FMS 연산 수와 스펙트럼 배열의 데이터량은 같다. PR #73에는 추가 메타데이터 읽기가 있다.
4. `sumPartitions`는 원본 320개 명령에서 PR #73 424개로 커졌고, 스택 프레임은 128→176바이트다. 주 MAC 반복문 내부의 벡터 레지스터 spill은 발견되지 않았다.
5. `accumulate`는 양쪽 모두 인라인된다. `sumPartitions`의 호출 경계도 동일하다. 새로운 함수 호출이 생겼다는 설명은 이 번역 단위에서 성립하지 않는다.

이는 실제 생성 코드에서 확인한 차이다. PR #74의 +40.00% 전체 비용을 각 원인에 몇 %씩 배분할 수 있는 하드웨어 카운터 실험은 수행하지 않았다. 캐시 미스·메모리 대역폭 부족을 확정 원인으로 주장하지 않는다.

## 기각하거나 보류한 후보

| 후보 | 결과 |
|---|---|
| NEON 루프 2배·4배 전개만 추가 | 원본의 paired load/store 구조를 완전히 복구하지 못함. 작은 커널의 개선 판정 통과 없음 |
| 상한을 `bins & ~3`으로 고정 | 실제 멤버 재읽기와 불필요한 꼬리 코드가 남음 |
| 상한 고정 + 2배 전개 | `sumPartitions`가 546개 명령으로 더 커짐. 정확성 검사는 통과했으나 최적화로 채택하지 않음 |
| Apple 수동 NEON 분기를 제거하고 원본 유지 | PR #74의 기존 대조군. 새 성능 개선 주장 없이 사용할 수 있는 보수적인 기준 |

상한 고정 + 2배 전개 후보는 기존 CTest 5/5, deadline 경로 66/66, 실시간 동등성 144경로, 동결 출력 2,645,088개 + fade 혼합 388,800개 float의 비트 일치, 추가 지연 0을 통과했다. 그러나 단일 callback screen에서는 control 48회, profile 37회의 wall deadline miss가 관찰됐다. 기존 p99 기준 통과가 miss 0을 의미하지 않는다. 다른 실행 환경의 수치와 직접 비교하지 않았다.

## 최종 원인 검증과 독립 후보

LLVM IR까지 확인했다. 원본의 자동 벡터 저장에는 `float` 타입 기반 alias 정보와 비중첩 정보가 있지만, PR #73의 명시적 NEON 저장에는 해당 정보가 없다. 실제 코드가 정수 멤버 `bins`를 반복해서 다시 읽는 현상과 맞물린다. `bins`를 지역 상수로 고정한 S4 후보에서 이 반복 읽기가 사라지는 것까지 확인했다.

최종 실험 후보 **S8T**는 지역 상수 고정 + 2배 전개 + scalar tail의 재벡터화 금지를 결합했다.

| 항목 | PR #73 | S8T |
|---|---:|---:|
| `sumPartitions` 정적 명령 수 | 424 | **272** |
| 스택 프레임 | 176바이트 | **96바이트** |
| 주 벡터 루프 안의 `bins` 재읽기 | 4-bin당 2회 | **0회** |
| 8-bin당 주 반복문 명령 | 46 | **29** |

S8T는 **기존 CTest 5/5, deadline 66/66, 실시간 동등성 144경로, 동결 출력 2,645,088 + fade 388,800 float의 비트 일치, 추가 지연 0**을 통과했다. 테스트·허용 오차·시간 한도를 완화하지 않았다.

[후보 패치](snapshot-candidate/S8T.patch)는 PR #73의 고정 소스에 적용하는 독립 실험안이다. 원본의 자동 벡터 루프는 여전히 8-bin당 24개 명령이므로, 코드가 작아졌다는 이유만으로 원본보다 빠르다고 판단하지 않았다. 최종 단일 screen의 wall miss도 control **14/19,200**, profile **16/19,200**으로 남아 있다. 다른 실행의 결과와 직접 비교해 개선율을 만들지 않았다.

**다음 승인 조건은 원본 A 대 S8T의 동일 환경 전체 callback 독립 비교다.** 이번에는 구조적 원인과 후보의 기존 계약 보존까지 확인했다. 성능 우위는 미입증이며 PR #73과 후보 모두 통합·출시 보류다.
