## 재현으로 확인한 추가 수정

`Tests/TunerGenerationTests.h`는 실제 JUCE worker를 명시적으로 일시 중지하고,
완전한 4096 decimated-sample 창을 한 번만 제공한다. 추가 입력으로 문제를 가리지 않는다.

1. **재활성화**: 기존 110Hz를 취득한 뒤 worker를 120ms 멈추고 disable/enable 후
   새 220Hz 창을 제공한다. #71은 새 FIFO까지 폐기하여 290ms 내 획득하지 못했다.
2. **입력 만료와 새 세대 동시 발생**: worker 450ms 중지, 입력 280ms 중단 후
   새 220Hz 창을 제공한다. #80은 생산자가 새 세대를 기록했어도 `expiredGap`에서
   새 창을 모두 폐기했다. 후속 입력이 없으면 끝내 획득하지 못한다.
3. 통합안은 history/이전 pitch를 초기화하되, **세대 변경이 확인된 경우** 현재 세대
   샘플을 보존한다. 세대가 같으면서 worker가 입력 만료를 발견한 경우에는 기존의
   보수적 전체 폐기를 유지한다. 현재 세대 필터와 원래 입력 타임스탬프의 250ms
   유효성 검사를 모두 통과해야 발행된다.

| 통제 검사 | 원본 결과 | 통합 후 첫 로컬 결과 |
|---|---|---|
| #71 재활성화 | FAIL, acquire=-1 | PASS, 122.386ms |
| #80 만료+새 세대 | FAIL, acquire=-1 | PASS, 172.423ms |

이 두 수치는 합성 창을 한 번에 큐에 넣는 **세대 회귀 검사**의 수치다.
실시간 오디오 32경로 응답시간이나 DAW 성능으로 확대하지 않는다.
드라이버 `generation-control.cpp`와 네 개 원시 로그를 동봉한다. 실제 CMake/JUCE
통합 실행에서도 같은 함수를 검사하며 macOS CI에서도 동일하게 실행한다.

## 유지되는 계약과 검증

- 획득 및 안정화 **각각 <290ms**, 최종 경로 오차 **<0.1 cent**, 기존 stable 관측
  조건, 576 pitch/18 stress 및 1,105 동결 kernel 비교를 변경하지 않는다.
- 4096 분석 창, 10ms worker 대기, >250ms stale 무효화, callback의 비차단 방식 유지.
- 생산자에 샘플별 generation 태그(64KiB)를 추가한다. 동적 할당/락/worker 깨우기를
  callback에 추가하지 않는다. 기존 worker QoS는 그대로 유지한다.
- `compatibility-files.json`: 추정기/스트로브 UI/TT·BFTS 프로파일/파라미터·직렬화가
  들어 있는 processor/editor, 버전과 정확도 검사 파일의 #71 대비 동일성 기록.
  파일 동일성이 실제 호스트 프로젝트 수용 검사를 대신하지는 않는다.
- 집중 CTest는 기존 5개에 재활성화/만료 후 복귀/cold mixed queue 3개를 더한다.
  CI는 `until-fail:3`으로 실행하고 전체 verbose 로그를 보존한다. 실패 후 재시도하여
  PASS만 취하는 방식은 사용하지 않는다.
- 전체 제품 `build.yml`, 집중 `signal-path.yml`, 별도 `graphical-eq.yml` 모두 PR
  `head.sha`를 체크아웃한다. 집중 성공을 전체 제품 통과로 간주하지 않는다.
- GitHub의 LastTest.log, JUnit, 원시 FEED/TIMING/DIAGNOSTICS 및 실패 경로를 보존한다.
  macOS 정상 QoS 대조군도 진단 결과로 보존하며 후보의 PASS를 대체할 수 없다.

실행 결과 및 동일 소스 SHA는 후속 `validation-status.json`/PR 본문에 기록한다.
실제 DAW·오디오 장치·청음 검증과 릴리스 승인은 이 변경의 로컬 검사와 별도다.
