# 베타테스터 연장 코드 발급 안내 (소유자용)

베타테스터에게 주는 코드는 베타 만료를 **무기한** 없앱니다. 한 번 입력하면 지금 베타와 **이후 모든 베타**(같은 비밀값으로 빌드한 버전)에 적용됩니다. 일반 사용자에게는 승인된 만료일(beta.2: 2027-03-31 23:59 KST)이 그대로 적용됩니다.

코드는 `CHT1-이름-확인문자6자리` 형태입니다(예: `CHT1-ZIEL-7K3Q9X`). 이름 뒤의 확인 문자는 비밀값으로 계산됩니다. 정상 코드 한 개에서 비밀값을 바로 구하는 구조는 아니지만, 확인 문자는 30비트뿐이며 비밀값 자체가 배포 바이너리에 포함됩니다. 무단 발급 방지 수단으로 간주하지 않습니다. [보안 검토](PR181_TESTER_SECURITY_REVIEW_20261026.ko.md)를 함께 확인하세요.

## 1. 처음 한 번: 비밀값 만들기와 등록

```sh
python Tools/tester_code.py secret --out "/안전한/경로/chimera-tester-secret.private.json" --show-secret
```

- `--show-secret`은 대화형 초기 등록 시에만 사용하세요. 기본 실행은 비밀값을 출력하지 않습니다. 터미널 녹화·공유 로그·CI에서 이 옵션을 쓰지 마세요.
- 출력된 64자리 16진수 값을 GitHub 저장소의 **Settings → Secrets and variables → Actions**에 `CHIMERA_TESTER_SECRET` 이름으로 등록합니다.
- PR 빌드에는 운영 비밀값을 전달하지 않습니다.
- 이 값이 없으면 릴리스 빌드(`build.yml`을 PR이 아닌 방식으로 실행)가 실패합니다. 값 없이 만든 빌드는 어떤 코드도 받지 않습니다.
- 비밀값 파일은 저장소·클라우드 공유 폴더·메일에 올리지 말고 오프라인 두 곳에 백업하세요.
- 비밀값을 바꾸면 이미 발급한 코드는 그 뒤 빌드에서 모두 동작하지 않습니다. 새 코드를 다시 발급해야 합니다.

## 2. 코드 발급

```sh
python Tools/tester_code.py issue --secret "/안전한/경로/chimera-tester-secret.private.json" --name ZIEL --name SINON
```

- 이름은 영문·숫자 2–16자입니다. 공백·점·하이픈은 빠지고 대문자로 바뀝니다(`Seo Mary` → `SEOMARY`, `K.loop` → `KLOOP`).
- 같은 이름은 언제 발급해도 같은 코드가 나옵니다. 발급 기록(이름, 날짜, 전달 방법)을 따로 남겨 두세요.
- 확인: `python Tools/tester_code.py verify --secret ... --code CHT1-ZIEL-XXXXXX`

## 3. 테스터에게 보낼 안내 (예시)

> Chimera 베타테스터 코드입니다. SETTINGS → **Enter beta tester code...** 에 `CHT1-ZIEL-XXXXXX`를 입력하고 APPLY를 누르세요. 이 컴퓨터에서는 지금 베타와 이후 베타가 만료되지 않습니다. 코드는 본인만 사용해 주세요.

- 대소문자는 상관없고, 확인 문자에서 O·I·L을 0·1로 잘못 입력해도 받아들입니다.
- 컴퓨터마다 한 번 입력합니다. 이미 열려 있던 다른 Chimera 창은 **RECHECK CLOCK**을 누르거나 다시 열면 적용됩니다.
- 코드는 그 컴퓨터의 사용자 설정에만 저장되고 프로젝트 파일에는 들어가지 않습니다.

## 4. 한계

- 현재 구현에는 코드별 취소 목록이 없습니다. 이미 배포되어 오프라인으로 실행되는 바이너리에 원격 취소를 소급 적용할 수 없습니다. 향후 빌드에 취소 목록을 넣는 설계는 가능하지만, 기존 바이너리에는 효력이 없습니다.
- 코드를 가진 사람은 누구나 쓸 수 있습니다. 이름은 발급 시 붙인 표시에 불과하며 실제 사용자 신원이나 기기 소유권을 증명하지 않습니다. 같은 정규화된 이름은 같은 코드를 받습니다.
- REMOVE는 이 사용자 설정의 파일만 지웁니다. 이미 복사한 코드나 다른 컴퓨터의 저장 파일에는 영향을 주지 않습니다.
- 비밀값은 릴리스 프로그램 안에 들어 있으므로 프로그램을 역분석하면 코드를 만들 수 있습니다. 기존 만료 정책과 같은 수준의 오프라인 제어이며, 변조를 막는 DRM은 아닙니다.

## 5. 저장과 삭제

- Linux/macOS에서 새로 저장·교체하는 코드 파일은 쓰기 시작부터 `0600` 권한을 사용합니다. 기존 코드 파일을 다시 APPLY하면 이 권한으로 교체합니다. Windows는 사용자 AppData 디렉터리의 ACL을 상속하며 다른 로컬 계정 접근 검증은 배포 전 확인 항목입니다. 관리자·동일 계정의 악성 프로그램·백업/동기화·사용자의 직접 복사를 막는 기능은 아닙니다.
- 삭제 실패 시 성공 메시지를 표시하지 않고 현재 권한 표시를 유지합니다. 성공한 삭제 후에도 이미 연주 중인 인스턴스는 유지되며, 새 인스턴스에는 원래 만료일이 적용됩니다. 다른 열린 창은 RECHECK CLOCK으로 저장 상태와 표시를 갱신합니다.
- 비밀값 파일은 Git 작업 디렉터리 안에 생성할 수 없고 기존 파일·심볼릭 링크를 덮어쓰지 않습니다. POSIX에서는 생성 시점부터 `0600`입니다. Windows 비밀값 파일은 별도로 사용자 전용 ACL을 확인해야 합니다.
