# 베타테스터 코드 발급·검증 안내 (소유자용)

코드는 `CHT1-이름-확인문자6자리` 형식입니다. **현재 main 계열은 HMAC-SHA256 방식**이며, 제품의 인증 코드와 소유자용 발급 도구가 같은 비밀값을 사용해야 합니다. 허용목록 방식의 별도 검토 브랜치와 혼동하지 마세요.

인증된 코드는 해당 컴퓨터의 베타 만료를 무기한 해제합니다. 같은 비밀값과 인증 구현을 유지한 후속 베타에도 사용할 수 있습니다. 버전 번호만으로 호환성이 보장되지는 않습니다. 일반 사용자의 beta.2 만료 정책은 2027-03-31 23:59 KST이며, 정책 승인과 릴리스 승인은 별개입니다.

## 발급과 빌드

1. 소유자용 `Tools/tester_code.py secret --out <비공개 경로>`로 비밀값을 만듭니다. 파일은 Git checkout 밖에 독점 생성하며 덮어쓰지 않습니다. POSIX에서는 처음부터 0600 권한을 사용합니다. 기본 출력에는 비밀값이 없습니다. 수동 등록이 필요할 때만 비공개 터미널에서 `--show-secret`을 사용합니다.
2. 같은 값을 GitHub Actions의 `CHIMERA_TESTER_SECRET`으로 등록합니다. 기존 코드가 있으면 **새 비밀값을 만들거나 교체하기 전에 기존 발급값과의 관계를 확인**해야 합니다.
3. `Tools/tester_code.py issue --secret <비공개 파일> --name <이름>`으로 발급합니다. 결과는 stdout에 나오므로 CI·공유 터미널·녹화·공개 로그에서 실행하지 않습니다. 원문과 발급 파일을 저장소에 넣지 않습니다.
4. `verify --secret <비공개 파일> --code <코드>`는 그 파일에 대한 소유자용 확인입니다. 코드가 명령 기록에 남을 수 있으므로 비공개 환경에서만 사용합니다. 이 결과만으로 실제 배포판의 수락을 보증하지 않습니다.

이름은 ASCII 영문·숫자 2–16자로 정규화합니다. 공백·점·하이픈·밑줄은 제거하고 대문자로 바꿉니다. 같은 이름과 비밀값이면 같은 코드가 생성됩니다. 확인 문자는 대소문자와 O→0, I/L→1 입력 보정을 지원합니다. Unicode 유사 문자와 과도하게 긴 입력은 거부합니다.

`build.yml`은 PR에서는 운영 비밀값을 전달하지 않습니다. 비PR 후보의 사전 검사와 세 OS의 CMake 구성 단계에만 전달하며, CMake도 누락·비hex·16바이트 미만·홀수 길이를 거부합니다. `prepare-release.yml`의 재사용 호출은 `secrets: inherit`을 사용합니다. 로컬 배포 후보에는 `-DCHIMERA_REQUIRE_TESTER_SECRET=ON`을 지정하세요. 비밀값 없는 일반 개발 빌드는 모든 테스터 코드를 거부합니다.

생성된 `ChimeraTesterSecret.h`는 빌드 입력이며 배포용 소스가 아닙니다. 소스·빌드 폴더 전체를 업로드하거나 CMake trace/환경 덤프에 비밀값을 기록하지 마세요. 이 방식의 제품 바이너리에는 인증에 필요한 공통 비밀값이 포함됩니다.

## 입력·저장·삭제

검증을 마친 정확한 배포 버전에서 SETTINGS → **Enter beta tester code...** → APPLY를 사용합니다. 성공하면 테스터 이름과 만료 해제 상태가 표시됩니다. **공개 `1.3.2-beta.1`에는 이 메뉴가 없습니다.**

- 코드 파일: JUCE의 사용자 application-data 디렉터리 아래 `SpectralForge/Chimera/beta-tester-code.txt`.
- 프로젝트·프리셋·A/B 상태에는 인증 권한이나 코드 원문을 저장하지 않습니다. 프로젝트 복원으로 삭제한 인증이 돌아오지 않습니다.
- 잘못된 코드나 저장 실패는 기존 인증을 바꾸지 않습니다. POSIX 파일은 처음부터 0600이며 임시 파일을 원자적으로 교체합니다. 최종 경로의 심볼릭 링크, 디렉터리와 비정규 입력 파일을 거부하고 읽기 크기를 제한합니다.
- REMOVE가 파일을 삭제하지 못하면 실패를 알리고 현재 인증 표시를 유지합니다. 성공 후 새 인스턴스에는 일반 만료 정책을 적용합니다. 이미 허용된 인스턴스의 오디오는 끊지 않습니다.
- 다른 창에서 입력·교체·삭제한 결과는 **RECHECK CLOCK** 또는 새 인스턴스에서 반영됩니다.
- 코드는 계정·기기에 묶이지 않은 bearer credential입니다. 기존 공유 허용 정책에 따라 다른 컴퓨터에서도 사용할 수 있습니다. 이름은 배정 표시이며 본인 인증이 아닙니다.

## 한계와 배포 확인

HMAC 방식은 개별 코드 취소를 지원하지 않습니다. 비밀값을 바꾸면 기존 코드 전체가 후속 빌드에서 무효가 됩니다. 바이너리에서 공통 비밀값을 추출하면 다른 코드를 만들 수 있고, 6자리 확인 문자는 30비트에 불과합니다. 강한 라이선스 보호나 DRM으로 간주하지 않습니다.

Windows의 실제 파일 ACL, Windows/macOS 설치·업그레이드, 실제 DAW/OBS와 공개 배포판의 코드 입력은 별도 확인이 필요합니다. 시험값으로 수행한 자동 회귀 테스트와 GitHub CI 성공은 실제 테스터 코드 5개의 배포판 수락 증거가 아닙니다.

2026-11-01 조사 근거와 미확인 항목은 [경로 검증 보고서](TESTER_CODE_PATH_AUDIT_20261101.ko.md)를 참조하세요. 이 문서는 신규 발급, 비밀값 교체, 후보 허용목록 적용, 릴리스 공개 또는 메일 발송 승인이 아닙니다.
